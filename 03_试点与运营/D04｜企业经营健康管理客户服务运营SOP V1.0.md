# D04｜企业经营健康管理客户服务运营SOP V1.0

**项目：** 企业经营健康管理\
**适用阶段：** 首批30天试运营及早期正式会员\
**组织模式：** 创始人主导 + AI辅助 + 专业事项外包\
**主要客户接口：** 微信或约定的企业微信\
**内部工具：** WorkBuddy、结构化表格、客户文件空间、必要的计算程序\
**关联文件：** B01、B02、B03、B03-1、B04系列、D01、D02、D03、D03-A

---

# 一、运营SOP的目标

本SOP不是为了把所有服务流程做得复杂。

而是确保即使只有一个人运营，也能够：

1. 不漏掉客户的重要事情。
2. 按约定时间响应。
3. 对每个客户形成持续、准确的经营理解。
4. 利用AI降低重复工作量。
5. 避免把错误分析发给客户。
6. 控制超出套餐范围的人工工作。
7. 让问题、机会和行动持续得到跟进。
8. 记录每家企业的实际服务成本。
9. 让后续增加人员时可以直接交接工作。

**核心原则：客户通过微信提出问题，后台按照标准流程处理。**

客户不需要理解内部使用了多少Agent，也不需要直接操作管理后台。

# 二、单人模式的职责划分

虽然初期只有创始人，但每项工作仍要区分角色。

| 工作环节   | 执行      | 审核与责任      |
| ------ | ------- | ---------- |
| 接收客户需求 | 创始人     | 创始人        |
| 需求整理   | AI辅助    | 创始人        |
| 经营档案更新 | AI辅助    | 创始人确认      |
| 数据计算   | 程序      | 创始人复核      |
| 经营分析初稿 | AI辅助    | 创始人审核      |
| 政策信息检索 | AI辅助    | 创始人核实      |
| 客户回复   | 人工发送    | 创始人负责      |
| 专业问题处理 | 外部专业机构  | 专业机构对其服务负责 |
| 跟进与提醒  | 系统提示+人工 | 创始人        |
| 收款和续费  | 创始人     | 创始人        |

即使AI能够自动生成正式内容，也不能默认允许它直接向客户发送重要经营判断。

# 三、客户完整生命周期

\<escape>线索 → 需求沟通 → 付费与授权 → 首次访谈 → 经营体检 → 持续服务 → 月度复盘 → 续费或退出\</escape>

建议采用以下标准状态：

| 状态   | 主要动作        | 进入下一状态的条件 |
| ---- | ----------- | --------- |
| 线索   | 记录来源及需求     | 客户同意沟通    |
| 意向   | 介绍产品和服务范围   | 客户确认体验    |
| 待启动  | 收费、协议、授权、排期 | 启动条件满足    |
| 建档中  | 访谈及数据盘点     | 完成经营理解    |
| 体检中  | 分析、报告、审核    | 报告可以交付    |
| 服务中  | 简报、问诊、监测、跟进 | 到复盘或期满    |
| 待续费  | 价值复盘及方案沟通   | 确认结果      |
| 正式会员 | 按套餐持续服务     | 周期性续费     |
| 已退出  | 关闭服务及资料处置   | 完成交接记录    |

每个客户应拥有唯一编号。

# 四、SOP-01｜签约与正式启动

## 输入

- 客户基本资料
- 已确认的体验或会员方案
- 服务起止日期
- 服务说明
- 付款记录
- 数据使用授权

## 执行流程

### 第一步：确认服务范围

向客户说明：

- 主要服务内容
- 工作时间
- 响应规则
- 首次体检安排
- 哪些服务需要另外报价
- 哪些经营结果无法保证

99元体验客户使用专门的体验服务说明，不自动套用399元或1299元会员的全部权益。

### 第二步：收费与留痕

确认：

- 收款金额
- 支付日期
- 收款主体
- 对应服务期限
- 99元正式签约抵扣规则

### 第三步：确认数据处理

说明：

- 需要什么信息
- 使用目的
- 使用的软件或服务商类别
- 是否涉及第三方专业机构
- 如何保存和处理资料
- 客户如何联系服务方提出更正或删除请求

涉及个人信息的具体处理方式，应按适用法律及服务协议执行。

### 第四步：建立客户档案

分配客户编号。

创建独立文件空间。

### 第五步：预约首次访谈

原则上安排60–90分钟。

## 完成标准

**客户清楚自己购买了什么，服务方清楚何时开始、做什么以及可以使用哪些资料。**

# 五、SOP-02｜首次经营访谈

## 访谈前

AI根据企业行业生成建议问题。

顾问查看客户已提供的信息，避免重复询问。

## 访谈中

遵守B03-1信息采集规范。

重点了解：

- 企业如何赚钱
- 客户从哪里来
- 主要产品与服务
- 成交、交付与回款方式
- 老板当前TOP3问题
- 近期重大经营变化
- 未来90天目标
- 当前有哪些可用数据

原则上先理解企业，再决定需要什么数据。

## 访谈后

使用AI形成：

**《企业经营基础档案草稿》**

顾问检查：

- 是否理解企业经营模式
- 是否遗漏重要业务
- 是否把老板估算写成客观事实
- 是否正确记录老板主诉
- 是否需要向客户确认

再生成：

**《定向补充资料清单》**

## 完成标准

能够用简单语言说明：

**这家企业主要靠什么赚钱，目前最关注什么问题。**

# 六、SOP-03｜客户资料接收与处理

## 6.1 可接收的资料

- Excel、CSV
- 收银系统导出
- 美团、抖音等平台数据
- 财务或业务报表
- 经营记录
- 截图与照片
- 客户授权提供的文字和语音资料

不默认要求客户提供：

- 账户密码
- 全量微信聊天记录
- 无关客户个人信息
- 完整银行流水
- 无关敏感资料

## 6.2 资料登记

每份用于正式分析的资料至少记录：

| 字段     | 内容           |
| ------ | ------------ |
| 客户编号   | 所属企业         |
| 资料编号   | 唯一标识         |
| 来源     | 谁提供、哪个系统     |
| 收到时间   | 日期时间         |
| 覆盖期间   | 经营数据日期       |
| 文件位置   | 保存路径或文件标识    |
| 使用目的   | 用于什么分析       |
| 处理权限   | 是否允许AI或第三方处理 |
| 质量状态   | 待检查、可用、有问题   |
| 最后更新时间 | 日期           |

## 6.3 使用前检查

- 是否属于正确客户
- 日期范围是否完整
- 关键字段是否存在
- 是否重复导入
- 统计口径是否明确
- 是否包含不需要的个人信息
- 是否需要脱敏

## 6.4 AI使用规则

只有明确允许用于相应处理场景的数据，才可以交给获准使用的AI服务。

对服务商的存储、模型训练使用、分包处理及跨境数据安排等，应事先确认适用条款。

未确认前，可以使用匿名化或脱敏后的示例数据完成工作流测试。

不能因为WorkBuddy具有企业版本，就直接推定所有客户敏感数据均可无限制上传。

## 完成标准

**重要资料来源可追溯，客户数据不会混入其他企业档案。**

# 七、SOP-04｜首次经营体检

## 7.1 确定分析范围

采用：

**通用体检底座 + 行业模块 + 老板主诉 + 可用数据条件。**

例如：

餐饮企业关注抖音套餐是否赚钱，优先选择渠道贡献分析。

商贸企业关注资金压力，优先选择应收和库存分析。

不是所有企业都执行同样深度的八维分析。

## 7.2 分析流程

**步骤一：数据盘点**

明确已经掌握哪些事实。

**步骤二：指标计算**

使用可靠的公式和程序进行计算。

**步骤三：异常初筛**

由AI辅助发现变化及可能问题。

**步骤四：证据整理**

区分事实、观察、推断、建议。

**步骤五：行业判断**

结合具体行业和企业经营模式理解问题。

**步骤六：生成报告初稿**

按B04老板版和行业模板生成。

**步骤七：人工复核**

重点审核数字、来源、经营逻辑和行动建议。

**步骤八：客户解读校准**

向老板解释重要发现，允许客户纠正。

**步骤九：正式归档**

形成经营基线、雷达和行动计划。

## 7.3 首次交付时效

沿用B02现行标准：

**在访谈及资料截止条件确认后，原则上5个工作日内完成首次交付。**

企业资料缺失时，可以交付带有明确限制的版本，但不能虚构缺失数字。

## 7.4 正式交付清单

至少形成：

- 老板版首次体检报告
- 企业经营基线V1.0
- 经营雷达V1.0
- 30天行动计划
- 内部分析与证据记录

# 八、SOP-05｜微信消息与经营问诊处理

这是日常运营最重要的SOP。**2026-10-13：M-L0免费轻量预服务按D06管理；付费会员客户的九类企业日常经营事务按B06分为快办/定制1:2互替并逐周记录；旧材料次数不与新权益叠加。**

## 8.1 客户消息统一处理流程

\<escape>收到消息 → 确认客户 → 识别需求 → 判断优先级 → 判断套餐范围 → 处理 → 审核 → 回复 → 归档 → 跟进\</escape>

不要仅仅在微信里回复完就结束。

涉及后续行动的事项必须进入服务记录或待办。

## 8.1-A 新增日常事务任务与例行服务的分账规则

客户简单经营问答、约定的周期性周报/提醒/顾问会议仍按B01/B02各档例行权益执行；**用户另行要求生成具体独立成果**（如销售话术册、活动宣传图、供应商比价表）才按B06快办/定制计入每周任务。接单时说清是免费L0的一次试做、会员日常事务、例行咨询还是另行专项；不把同一交付重复扣次。系统记录企业匿名ID、任务类型、预计工作量、实际工时、一次合理修改与审核状态。未经授权不可自动读取微信历史对话。

## 8.2 需求分类

| 类型   | 常见例子         | 处理方式      |
| ---- | ------------ | --------- |
| 简单问答 | 一个经营问题怎么看    | AI辅助，顾问回复 |
| 经营数据 | 帮我看看营业额变化    | 数据核对与计算   |
| 经营材料 | 写一个活动方案      | 判断材料级别    |
| 外部机会 | 有什么合适政策      | 检索与资格初筛   |
| 资源需求 | 帮我找会计或供应商    | 资源筛选与授权对接 |
| 重要事项 | 合同快到期、客户催款   | 登记、提醒、跟进  |
| 专业事项 | 正式法律、税务、审计问题 | 专业转介      |
| 大型项目 | 开新店、完整系统开发   | 单独评估报价    |

## 8.3 首次响应

沿用B02：

| 客户  | 工作时间首次响应      |
| --- | ------------- |
| 基础版 | 1个工作日内        |
| 标准版 | 工作时间2小时内      |
| 顾问版 | 工作时间1小时内，优先处理 |

服务时间为工作日9:00–18:00。

响应指确认收到需求并告知初步处理安排，不等于事项已经完成。

免费M-L0响应/排期在预服务开始前明确，不得让免费客户误认为享有正式会员所有响应时限；新客户不再提供99元体验。

## 8.4 单人值守方式

试运营初期建议：

- 开启已签约客户的消息通知。
- 在工作时间安排固定检查节点。
- 对需要2小时内响应的客户，不得只在早晚各看一次微信。
- 外出访谈或长时间会议前，提前处理临近响应期限的事项。
- 顾问版1小时响应必须具备可靠通知和值守能力。

如暂时无法稳定履行较高时效承诺，应控制接单范围，而不是接单后再解释人手不足。

## 8.5 简单问题回复模板

客户问：

“这个活动值不值得做？”

不直接回答：

“值得做。”

而应先确认：

- 活动目的
- 预计投入
- 产品或服务
- 目标客户
- 预期结果

回复结构：

**目前怎么看 → 判断依据 → 还缺什么 → 建议先做什么。**

## 8.6 工作量升级规则

如果预计单次需求明显超过30分钟：

先判断是否属于已经约定的材料、经营分析或专项权益。

如超出范围，向客户说明工作量及可能的另外收费。

获得确认后再推进。

内部工时预警不能替代现有合同权益。

# 九、SOP-06｜每周经营健康简报

## 9.1 生成时间

根据客户实际服务周期安排。

建议每周固定一个工作日生成，不强制所有客户在同一天收到。

## 9.2 信息来源

- 企业本周提供的数据
- 现有经营档案
- 客户新提出的问题
- 未完成行动事项
- 已核实的外部机会
- 重要日期和风险信号

## 9.3 内容结构

老板版建议尽量简短。

### 本周你需要知道什么

1. **生意变化：** 有数据时说明。
2. **值得注意：** 有问题时说明。
3. **一个机会：** 有真实匹配信息时提供。
4. **正在处理：** 重要待办进度。
5. **下周建议：** 一项具体行动。

没有重要变化，不强行生成“重大异常”。

## 9.4 内部生成流程

AI初筛 → 资料与计算核验 → 顾问审核 → 微信发送 → 服务记录更新。

## 9.5 简报质量标准

- 尽量让老板3分钟左右看完
- 不堆砌行业新闻
- 不输出未经核实的政策资格
- 每个重点最好对应行动意义
- 数据没更新时明确说明
- 不把AI推断写成确定事实

# 十、SOP-07｜重要风险与机会提醒

不是所有变化都要打扰老板。

## 10.1 普通信息

例如常规行业新闻。

进入周报或内部观察，不单独提醒。

## 10.2 值得关注

例如：

主要客户采购连续减少，或某项政策可能符合企业条件。

顾问核实后发送简短提醒。

## 10.3 需要尽快处理

例如：

已经确认的重要申报截止日期即将到来，或者企业报告了可能造成重大经营损失的事项。

在约定服务时间内优先处理。

涉及事故、违法风险或高度专业化事项时，应建议客户及时联系主管部门或具备资质的专业人员，不能把本服务包装成24小时应急服务。

## 10.4 提醒标准结构

**发生了什么？**

**为什么与你有关？**

**现在应该怎么办？**

**是否需要我们继续协助？**

例如：

“你之前提到准备扩大门店。我们查到一个相关的公开扶持项目，但目前还需要确认企业类型及申报条件。建议先核对资格，不宜直接按确定能够获批来安排资金。”

# 十一、SOP-08｜30天行动计划跟进

首次体检形成TOP3优先事项。

每个事项必须有：

- 行动内容
- 企业负责人
- 计划完成时间
- 当前状态
- 顾问支持事项
- 需要的证据或结果

建议状态：

**待确认｜未开始｜进行中｜等待客户｜等待第三方｜已完成｜已取消。**

## 每周跟进

只跟进实际需要推动的事项。

例如：

“上次说的两家采购下降客户，这周有没有联系？如果已经沟通，我可以帮你整理一下下一步方案。”

客户决定取消或暂缓的事项，应记录原因，不无限催促。

# 十二、SOP-09｜资源推荐与专业转诊

## 标准流程

**确认需求 → 判断资质边界 → 寻找候选机构 → 初步核实 → 报客户选择 → 获得授权 → 对接 → 结果跟进。**

## 顾问应确认

- 客户真正需要什么服务
- 是否需要法定专业资质
- 对方是否有相应能力或资质
- 大致费用和工作范围
- 是否存在转介利益
- 是否需要交换客户资料

## 不能做的事

- 未经同意向第三方发送客户资料
- 假称专业机构为官方指定单位
- 保证专业机构一定解决问题
- 将需要资质的正式专业意见作为AI自动交付

专业机构的工作范围、收费、责任和合同主体应明确。

若项目本身承担总包或转委托责任，需要另外评估合同和法律风险。

# 十三、SOP-10｜每月经营复盘与服务价值账单

## 13.1 月末复盘内容

- 本月重要经营变化
- 已处理的问题
- 发现并核实的机会
- 已完成行动
- 尚未解决的事项
- 下月优先事项
- 客户反馈

深度依据套餐确定。

## 13.2 服务价值账单

记录实际交付：

| 维度   | 示例           |
| ---- | ------------ |
| 经营分析 | 完成一次平台收入核对   |
| 经营提醒 | 提醒证照即将到期     |
| 材料服务 | 完成一份活动方案     |
| 资源服务 | 推荐两家符合条件的服务商 |
| 行动跟进 | 推动一个应收核对事项   |
| 经营成果 | 客户确认的实际改善结果  |

客户没有实际取得的收入或节省金额，不得写成已创造收益。

## 13.3 续费沟通

正式会员到期前，按照协议和合理沟通节奏提醒续费。

30天体验结束后，不自动扣款。

99元体验费在客户正式购买会员时全额抵扣，记录抵扣明细。

# 十四、SOP-11｜客户数据隔离与保密

## 14.1 每家企业独立管理

建议文件结构：

**客户编号 / 基础档案 / 授权与协议 / 原始资料 / 分析底稿 / 正式交付 / 服务记录 / 财务记录**

## 14.2 数据分级

### A类｜公开信息

可正常检索和引用，但注意时效与来源。

### B类｜企业内部经营资料

仅在授权范围内用于该企业服务。

### C类｜高敏感或涉及个人信息的资料

例如客户联系方式、员工详细资料、合同中的个人信息等。

仅在必要且具备相应合法处理条件时使用，加强访问和传输控制。

不同资料可能同时涉及商业秘密和个人信息，应分别满足对应保护要求。

## 14.3 资料发送检查

每次发送正式报告或敏感附件之前：

1. 核对收件企业。
2. 核对文件名称和版本。
3. 核对是否混入其他客户信息。
4. 核对敏感数据是否需要脱敏。
5. 核对收件人与授权范围。
6. 发送后更新交付记录。

## 14.4 数据保留与退出

数据保存期限、客户访问方式、删除安排和备份清理，依据合同及适用法律确定。

客户退出时：

- 停止后续服务任务
- 处理未完成事项
- 确认需返还或删除的资料
- 保存依法或依约必须保留的必要记录
- 撤销不再需要的系统访问权限

不在合同尚未约定时擅自确定永久保存客户原始资料。

# 十五、SOP-12｜错误、投诉与异常处理

## 15.1 经营数字错误

发现报告数字有误：

- 暂停继续引用错误数字
- 核对原始来源与公式
- 识别受影响的判断
- 更正正式交付内容
- 主动向相关客户说明
- 记录错误原因及预防措施

## 15.2 错发客户信息

发生疑似数据泄露或错发：

- 立即停止继续传播
- 采取撤回、隔离或访问限制等措施
- 记录事件和受影响范围
- 评估是否需要依法通知相关人员或主管部门
- 采取补救措施
- 必要时寻求专业法律及安全支持

具体通知义务与时限应依据事件情况及适用法规判断。

## 15.3 客户不满意

先确认：

- 对哪个结果不满意
- 是否存在服务承诺未履行
- 是否为结论不同意
- 是否属于额外需求
- 是否可以修正或补充说明

不要自动把客户不同意分析结论视为客户不配合。

## 15.4 服务逾期

需要记录：

- 应完成时间
- 实际完成时间
- 逾期原因
- 影响范围
- 客户沟通结果
- 后续修正措施

# 十六、每天怎么运营

以下为单人模式推荐工作节奏，不代表每一天都必须制作所有交付物。

## 上午：处理客户与重要事项

**09:00左右**

- 检查客户消息
- 查看当天到期任务
- 确认需要快速处理的事项
- 查看AI整理的机会及异常候选

**上午后续时间**

- 回复经营问诊
- 处理当天必须完成的任务
- 安排访谈或客户沟通

工作时间需结合会员响应标准保持足够频率的消息检查或可靠通知，不能仅靠早晚两次查看。

## 下午：交付与客户开发

- 数据分析
- 经营报告
- 客户访谈
- 材料审核
- 资源协调
- 新客户沟通

## 下班前：检查服务闭环

- 是否有未回复的客户
- 是否有即将逾期的任务
- 今天完成了什么服务
- 哪些事项需要明天跟进
- 工时是否记录
- 是否存在客户数据或发送风险

# 十九、WorkBuddy最先实现的五个流程

## 流程一：客户访谈整理

输入：

经授权的访谈记录。

输出：

企业档案草稿、老板主诉、待确认问题。

审核后进入正式档案。

## 流程二：客户需求分类

输入：

人工登记的客户消息或授权接入的信息。

输出：

工单类别、可能优先级、预计处理步骤。

不直接自动承诺完成时间或对外发送。

## 流程三：经营简报生成

输入：

最新经营信息、待办和外部机会。

输出：

简报初稿、待核实信息清单。

顾问确认后发送。

## 流程四：行动事项跟进

输入：

各企业行动计划与到期日期。

输出：

内部待办提醒和客户跟进建议。

不自动重复打扰客户。

## 流程五：服务工时与价值统计

输入：

服务记录、完成事项、实际耗时。

输出：

每客户工时、成本分析、月度价值账单初稿。

用于D03模型校准。

**这五个流程比一开始开发复杂经营驾驶舱更优先。**

# 二十一、试运营阶段的验收指标

第一阶段不追求SOP表面上全部自动化。

重点验证：

**流程完整性**

每家试点能从签约、建档、体检一直完成30天复盘。

**交付准确性**

正式发送的数据和重要判断经过审核，没有明显且未纠正的错误。

**响应可靠性**

达到已约定的响应标准，并记录实际情况。

**成本可追踪**

可以计算每家客户的获客、体检、日常服务和复盘人工时间。

**客户实际使用**

能够识别客户真正使用了哪些服务。

**AI实际效率**

能区分AI减少的工作与AI增加的审核、纠错工作。

**可复制性**

第二家同类型企业不需要从零设计全部分析和交付流程。

# 二十二、何时需要调整单人模式

出现以下情形时，应评估合作人员、兼职运营或进一步自动化：

- 已承诺的响应开始频繁超时。
- 新客户建档长期积压。
- 每周交付持续挤占所有开发时间。
- 大量时间花在重复数据整理。
- 客户数量增长但服务满意度下降。
- 创始人已无精力继续拓展客户。
- 顾问版和专业问题超出个人能力范围。

增加人手前，先确认究竟是：

**服务范围过重、流程不合理、工具不够用，还是客户规模真的需要新岗位。**

不要将所有效率问题直接通过招聘解决。

# 二十四、最终执行原则

**每个客户都要有档案。**

**每件重要事情都要有记录。**

**每条经营判断都要有依据。**

**每项行动都要有人跟进。**

**每份正式输出都要经过审核。**

**每一段人工投入都要能够核算。**

最后形成的服务体验应该是：

> **老板只需要通过微信找我们，后台自然有人持续了解企业、整理信息、分析问题、提醒事项并跟进结果。**

即使初期这个“有人”主要就是创始人本人，也应该从第一天按照可复制的标准运行。
