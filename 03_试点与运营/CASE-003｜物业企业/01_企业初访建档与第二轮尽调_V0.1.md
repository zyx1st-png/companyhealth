## 2. 客户需求与实地新发现

### 2.1 客户显性经营诉求（访谈）

- **物业费收缴不顺畅**：对话方主动反复谈到业主缴费不积极，以及需要寻找新经营办法。
- **希望拓展物业费以外的收入**：社区便民、日用品与适老服务被讨论过；方向性认可不等于预算和内部执行承诺。
- **现有服务承接薄弱**：物业线上入口主要承担缴费和沟通，家政、维修等第三方服务统一承接能力尚不明确。

### 2.2 影响商业可行性的补充观察（项目方）

1. **微信收款＋Excel台账**：可能存在对账耗时、信息割裂和收费主体不清等改进空间，但**尚未发现经过核实的错漏、挪用或财务损失**；不能直接断言有系统采购必要。
2. **部分欠费可能是有意行为**：若欠费主要来自长期争议、拒缴而非提醒遗漏，普通催缴系统与AI提醒的回款增量可能很小；需依据分类数据验证。
3. **社区线上使用频率偏低**：在缺少有效触达与复购数据之前，社区商城、线上会员和订单平台的单位经济性存疑。
4. **一线执行能力可能有限**：任何新流程都需要低门槛和明确责任人；否则外部顾问可能被动承担长期人工执行工作。

**当前商业判断**：客户有真实诉求迹象，但暂未证明存在**可由外部服务商控制、低成本改善、能让客户支付服务费**的问题。不能将“经营痛点明显”直接等同于“项目值得做”。

## 3. 机会清单与初步取舍

| 候选方向 | 可能价值 | 当前主要障碍 | 当前动作 |
| --- | --- | --- | --- |
| 物业收费数据与对账流程 | 若错漏和人工重复劳动显著，可降低对账成本、提高账目可追溯性 | 现有 Excel 未必造成实质损失；收款主体及数据使用权限待核 | **只调查，不预定系统建设** |
| 欠费原因结构与收缴改善 | 若存在可解决的账单／服务争议或缴费摩擦，可改善部分回款 | 可能有大量主观拒缴；诉求处置取决于物业自身行动 | **只测可改善欠费占比，不承诺收缴率** |
| 物业服务与业主关系修复 | 分类投诉、整改追踪或服务信息公开可能帮助长期信任 | 人员、预算和服务质量的根本问题非顾问可单方改变 | 条件满足后探索 |
| 社区增值服务／适老服务 | 可能引入服务商与新收入 | 线上低频、履约成本、业主支付意愿未知 | **降优先级，暂不建设平台** |
| 物业资源与本地企业渠道合作 | 物业或有场地、业主触点及其他项目资源，可用于B端商户合作 | 资源可调度权、合规宣传渠道与商家付费意愿未知 | 低成本保留观察 |

**现阶段不建议**：自行垫资建设商城／小程序、承诺物业费回收额、承担逐户催缴、未经授权处理业主联系方式与欠费明细、为低频运营设置常驻团队。

## 4. 第二轮尽调：优先索取的数据与问题

**目标**：用一次有边界的沟通与少量汇总资料，判断客户是“可付费经营服务对象”“资源合作对象”还是“暂缓跟进”。不默认进入30天运营试点。

| 优先级 | 需要核实 | 最小数据／具体问题 |
| --- | --- | --- |
| P0 | **实际主体和决策权** | 哪家公司签物业服务合同、谁实际收款、谁承担收支、谁能决定服务预算？管理多少个小区？ |
| P0 | **物业费应收与实收** | 最近12个月应收总额、实际到账、期初／期末欠费余额；账面数据及统计口径，按月份汇总即可 |
| P0 | **欠费结构和原因** | 按拖欠年限、是否存在服务争议、是否仍居住等分组的户数／金额；“故意欠费”估计依据是什么？ |
| P0 | **现有收费流程** | 付款码收款主体、到账账户、业主与账单匹配办法、Excel样表字段、核对周期、错漏类型／数量；**首轮仅看去标识样例** |
| P0 | **物业实际可支配预算** | 公司收支与人工成本的汇总区间、改善收缴愿意投入的预算、是否安排内部负责人配合 |
| P1 | **物业服务现状** | 主要投诉类别和处理周期、当前法律／合同争议、物业能否实际落实整改 |
| P1 | **组织执行能力** | 收费、客服、维修分别多少人，谁会使用表格，员工是否有可承担轻量试点的人时 |
| P1 | **社区经营与渠道** | 公众号／微信群的去标识活跃指标、居民主动服务咨询次数、已合作商家、公共空间及可合法提供的合作位置 |
| P1 | **规模与发展** | 准确管理户数、入住比例、管理项目数量、其他可复制项目；居民画像只接受必要的汇总统计 |

**资料获取原则**：先看**汇总数据、空白表结构和现场流程演示**，不直接索取业主名单、手机号、住址、原始银行／微信收款流水、欠费个人明细或第三方私人信息。若必须处理真实资料，先明确物业授权、用途、范围与保护措施；此公开仓库只保存审阅后可公开的汇总结论。

## 5. 第二轮结束后的决策门槛

| 结果 | 触发条件 | 建议行动 |
| --- | --- | --- |
| **A｜考虑专项服务** | 有可核实的重复劳动／差错或可控收缴障碍；负责人明确预算、内部配合人和验收指标 | 先做**小范围固定交付专项**，再讨论持续伴随服务；另行定价、授权和合同 |
| **B｜考虑资源渠道合作** | 物业具备可合法使用的场景／合作资源，且有商家表达付费合作意向 | 不承接居民端长期运营，以B端合作撮合／项目制为主 |
| **C｜继续观察** | 有一定需求但关键数据、预算或执行人尚未明确 | B-线索保留，约定补充数据后再议；不免费投入完整方案 |
| **D｜停止主动投入** | 无预算或决策权、核心数据无法核验、预期增量小于运营成本、负责人无法配合 | 降为普通关系维护，不开发工具、不建群、不承担催缴 |

**复评原则**：B-仅是本次跟进意向，不随内部想象提高。第二轮必须回答“**能否创造净增价值、谁实际执行、谁为交付付费、项目的退出成本是什么**”。没有证据时可以选择 C 或 D，不预设继续合作。
