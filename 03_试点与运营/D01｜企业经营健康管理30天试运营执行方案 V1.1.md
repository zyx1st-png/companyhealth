# D01｜企业经营健康管理首30天试运营执行方案 V1.1

**2026-10-13作者产品决策修订**：本版替代旧99元30天付费体验运营流程，新客采用M-L0免费7–14天（D06）→199/399/1299元起会员，P线继续按B08/C08做P-L0和高级专项。首30天M/P各42.5小时**合计仍是原85小时双线经营池**；具体资源和D7/D14/D30节点以V02为准。本文件不是实际订单或成交报告。

## 一、首轮验证目标

1. M线：检验免费、低信息门槛的初次接触能否使企业真实使用一次服务、认可定向信息并愿意**直接按月持续付费**。
2. 验证按B06的日常经营事务9类场景、快办/定制1:2互换是否可控交付，特别是实际人工分钟、核验质量和修改率。
3. P线：寻找明确愿意考虑付费的单项经营问题，争取书面范围和报价；同一企业双线分别记录。
4. T线：优先验证可审稿、可复核的人工闭环；模拟效率不是市场需求证据。

## 二、客户范围与入口

初期选择3–5家愿意沟通的小微企业候选，优先来自熟人及自愿协会转介绍（不默认取得协会名单和私人联系方式）；业务类型尽量多样，但首批避免无法界定资料来源的高敏感项目。避免把访谈对象数量误称付费会员数。特殊情况可直接P-L0，不要求先M-L0。

## 三、M线客户流程

**D1–D7：** 列匿名候选与联系人同意状态，安排1–2家轻访谈，完成企业V0.1最小建档、公开信息核验、首次机会简报与1次轻量事务体验；记录实际时间。L0是限时帮助，不要求企业先交账本，也不无偿交付完整诊断。

**D8–D14：** 陆续分批新客户；已启动的M-L0按其约定的7–14天窗口继续做1–2次有价值信息跟进、有限问询与反馈。合适客户明确说明三档实际权益及定制与快办区别；自愿转月费或退出。

**D15–D21：** 对已付款会员按B01/B02/B06兑现内容制作次数、周报/问诊等单独权益；对未付款的L0停在免费边界。使用D04微信手工服务记录，必要时调整新客容量。

**D22–D30：** 对应V02评估免费→真实使用→正式签约/实收→正式交付→续费意向各节点；未到首月续费点不能提前声称已续费。

## 四、任务和工时管理

M线全部访谈/获客、建档、免费L0、正式服务、修改、售后和复盘都计入**42.5小时/月规划池**。P线同口径另计42.5小时；公共技术20小时、运营合规15小时、协会公益上限12小时，不可双算。在客户问询、主动周报、制作交付三类实际工时中分栏。B06轻量5–10分钟、复杂15–30分钟仅为检验目标，不是服务事实保证。

## 五、服务质量与边界

免费阶段只获取自愿提供且必要的数据；对外市场、政策和企业经营信息标明来源或不确定性。需要财务测算时由可靠工具确定性计算；用AI整理材料时必须人工复核事实、数字、广告宣传和素材授权。无G10收费主体/数据门槛不得开正式收费；无客户授权不得扩大数据用途。先确认范围、交付时间和修改口径，P01–P04完整专项从会员权益外报价。

## 六、30天阶段证据与裁决

记录真实接触→合规授权→有效L0→简报实际有用→一次快办交付→正式报价→实收会员月费→首次交付→续费/不续费，分母和日期清楚。辅助记录每类任务实际工时/返工及客户从事务服务转向经营问题交流的行为。第30天按V00/V01/V02分别裁决M/P/T的Go/Adjust/No-Go；不能用AIGC模拟效果或人情支持代替持续付费证据。
 
## 七、四类核心服务的试点观察（恢复旧D01 §6 的非99元内容）

| 旧D01能力 | 当前试点可承诺的范围 | 实际观察 |
|---|---|---|
| 看经营 | 免费期先理解企业业务与重点问题，**不提供完整体检**；付费后首次服务按199简版画像／399重点访谈摘要／1299深入议题分层 | 是否能提出可核验且企业实际关注的问题 |
| 找机会 | 以公开且可核验来源，筛选可能相关的政策、市场和合作线索 | 信息是否被阅读、追问与使用 |
| 处理事 | M-L0提供一次轻量快办；正式会员按B06轻量/复杂周次数及混用规则执行 | 请求频次、工时、返工、实际使用与延伸经营问题 |
| 找资源 | 仅在真实需求下推荐来源明晰、已核实或标明待验证的专业资源 | 是否发生有效沟通，不用“推荐”冒充合作成交 |

## 八、最小运营台账与七类记录（恢复旧D01 §8.1）

首期采用微信/企业微信 + WorkBuddy辅助 + **人工维护的隔离表格与文件夹**，不以建成SaaS为启动条件。以下是**业务逻辑表**，不是必须开发七张数据库表；与MVP候选六张表可通过视图或字段映射，不擅自新增数据库表数。

| 逻辑记录 | 最小字段 | 安全边界 |
|---|---|---|
| 企业表 | company_id、行业、客户关系阶段、套餐、服务期、合法联系许可 | 联系方式单独受控，不上传Git |
| 企业档案表 | 经营模式、主要客户/渠道、老板关注、资料可用性、来源与更新时间 | 仅经授权收集最小必要内容 |
| 服务记录表 | 服务类型、收到/确认/交付时间、负责人、状态、人工分钟、审核与反馈 | 区分免费L0、例行、轻/复杂任务、P线 |
| 问题与机会表 | 发现时间、公开来源、事实/推断、企业相关性、状态 | 不把预测当事实 |
| 经营监测表 | 指标名称、来源、更新周期、校验方式、最近检查时间 | 数字用确定性程序计算 |
| 行动事项表 | 客户确认的动作、责任人、期限、下一次跟进 | 不替客户未经授权执行经营决定 |
| 商业验证表 | 渠道、免费试用、报价、真实到账、付费档位、续费、拒绝原因 | 免费转化与真实付款必须分开 |

WorkBuddy优先用于整理已授权访谈、生成草稿、机会初筛、核对任务清单和脱敏管理汇总；不得自动读取私人微信数据库或自动对外发送。模型处理资料依CLAUDE/T00/G05分级授权，人工确认对象及重要数字。

## 九、工作量分账与双线容量（恢复旧D01 §7）

至少分别记录**获客触达、免费访谈、最小建档、首次正式体检、公开信息核验、例行周报、问诊、两类事务处理、合理修改、资源介绍、月度复盘、专项报价与履约**的实际人工分钟；另记工具现金支出和模型费用。免费期超配不得转化成正式客户默认权益。

原旧D01对付费99元30天体验的5.5–12.5小时估算**已失效**；现在只按D06免费的有限范围实测。首30天规划仍M线42.5小时、P线42.5小时。满额首月压力测算按H03，**不允许仅用AI生成速度估算人工工时**。当前新客拟试运行B06的199=1复杂/2轻、399=2复杂/4轻、1299=3复杂/6轻（按周互替），复杂份额不降，故H03复杂任务上限压力表仍适用。

## 十、D7／D14／D30证据与四项裁决（恢复旧D01 §10–§11）

| 验证维度 | 可观察事实 | 不可代替的证据 |
|---|---|---|
| A 需求成立了吗 | 主动提问、使用体验成果、明确继续关注的事项、正式报价反馈 | 口头称赞不等于真实付款 |
| B 服务成立了吗 | 经营简报/提醒/问诊/日常事务的使用证据，而不只是首次出图 | 免费演示不等于持续使用 |
| C 交付成立了吗 | 公司隔离、来源与数字核验、人工审核、时效、返工及P90人工工时 | 模拟质量不等于真客户稳态效率 |
| D 商业模式成立了吗 | 正式月费实收、履约工时、续费（到期时）、可归属获客成本 | 免费M-L0不能算收入 |

- **D7**：检查同意、最小建档、首个机会简报及免费快办是否真实交付，登记每项人工分钟。
- **D14**：复核免费服务是否真正有用、主动跟进与报价意愿、客户资料清理计划；到期的M-L0不继续无偿履约。
- **D30**：按照V00/V01/V02作Go／Adjust／No-Go裁决；真实签约与到期续费分开计，P线合同与收入独立记账。

初步判断：出现真实付费、持续使用、且工时有收敛趋势才考虑扩大；使用少或人时高则先调整；免费依赖严重、未授权或已影响已签客户履约时暂停新客。

## 十一、必须形成的六项内部成果（恢复旧D01 §12）

1. 首批企业需求和行业差异分析（匿名、只含授权摘要）。
2. 服务使用与成本报告（免费L0、会员例行、事务、P专项分开）。
3. AI辅助实际节省人工时间与错误分析（真实与模拟分开）。
4. 免费→正式月费成交/拒绝原因和定价复盘。
5. MVP最小开发需求优先级修订（痛点驱动，不先开发配额引擎）。
6. 第31–90天是否继续M/P均衡、调整或停止扩大规模的裁决。

## 十二、三条执行红线（恢复旧D01 §13）

- **不制造经营成果**：尚未落实的机会不是成交，模拟预测不是客户收益。
- **不无限免费或隐性超配**：可自主做小规模额外帮助，但必须记工时，不把其写为永久会员承诺。
- **不为了速度牺牲数据安全**：客户授权、跨企隔离、AI分级、数字程序核验与人工审批是硬门槛。
