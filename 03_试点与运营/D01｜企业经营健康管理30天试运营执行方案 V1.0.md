# D01｜企业经营健康管理30天试运营执行方案 V1.0

**项目：** 企业经营健康管理\
**阶段：** 商业模式验证\
**试运营周期：** 每家企业30天\
**目标规模：** 首批5–10家中小企业\
**文档性质：** 内部创业执行方案

---

> **分轨说明**：本方案仅覆盖M会员线99元/30天体验；P01–P05专项独立按B08执行。合同、工时、收入与客户人数汇总遵V00/H01，同一企业两份合同不能算两家企业。

## 一、试运营的真正目的

本项目不以首次经营体检报告为最终产品，而是通过AI经营助手与专业顾问，为企业提供长期经营支持。

30天试运营不是为了证明AI能生成报告，也不是为了证明能收集大量经营信息。

本次试运营最需要回答五个问题：

**1. 企业是否真的需要这项服务？**

老板是否愿意让一个外部经营助手持续参与经营信息整理、问题分析和事项跟进。

**2. 什么服务最容易让老板感受到价值？**

是经营体检、政策机会、日常问诊、数据分析、资源连接，还是持续提醒？

**3. 企业愿不愿意提供必要信息？**

在不要求企业更换系统的前提下，能否建立持续更新的经营档案。

**4. AI能否显著降低顾问的服务成本？**

哪些工作可以自动化，哪些仍需要人工判断与沟通。

**5. 企业30天后是否愿意正式付费？**

最终验证的是长期服务关系，而不是一次性报告满意度。

---

## 二、试运营产品

对外统一采用：

### 企业经营健康管理｜30天体验计划

**试点费用：99元30天体验服务费。**

收费性质、不退款边界、会员抵扣和不自动续费规则，以D02第八节为准；正式购买会员时全额抵扣。

99元仅作为试运营参与机制，不新增第四档正式会员。

在实际收费前，应书面明确：

- 体验的起止日期
- 99元的抵扣条件
- 不转正时的退款或结算规则
- 体验包含的服务范围
- 额外服务是否收费
- 企业提供数据的使用范围

避免客户误认为99元包含无限经营咨询或完整专项分析。

### 对外交付

每家试点企业获得：

1. 一次企业经营访谈
2. 一份适合企业行业与数据条件的首次体检报告
3. 一份30天重点行动计划
4. 一套企业专属经营监测清单
5. 约定的每周经营简报
6. 重要风险、机会和事项提醒
7. 体验期内约定范围的经营问题协助
8. 一次期末复盘与正式会员方案建议

不承诺在30天内解决企业所有经营问题。

---

## 三、首批客户如何选择

不建议首批完全随机招募。

首批试点要能够同时检验：

- 服务价值
- 行业适配
- 数据获取
- 老板参与度
- 顾问交付成本
- 后续付费意愿

### 3.1 建议客户结构

以8家作为计划基准，实际允许5–10家。

| 企业类型     | 建议数量 | 主要验证方向          |
| -------- | ---: | --------------- |
| 餐饮、零售或门店 |   3家 | 营业额、渠道、产品、门店    |
| 商贸、批发、经销 |   3家 | 客户、应收、库存、经营机会   |
| 工程、制造或服务 |   2家 | 项目、执行、行业适配与通用服务 |

8家是便于组织试点的建议配置，不是必须达到的行业比例。

### 3.2 优先选择的企业

- 老板或主要负责人能够直接参与沟通
- 企业已经有实际持续经营业务
- 至少存在一个老板真正关心的问题
- 有意愿讨论经营情况
- 能够安排基本访谈
- 愿意对服务提出真实评价
- 有一定续费可能性

不强制企业提供完整财务数据。

### 3.3 不宜优先选择

- 只希望免费领取报告的企业
- 完全不愿进行经营访谈的企业
- 期待立即获得贷款、订单或补贴保证的企业
- 要求项目代替律师、会计师等专业人员出具正式意见的企业
- 主要需求是长周期、重人工专项项目的企业

后两类客户可以保留为专项服务线索，但不宜全部计入标准化会员服务试验。

## 四、试运营的完整服务流程

每家企业独立计算30天。

建议分批启动，不要让所有企业在同一天完成访谈和资料提交。

### 阶段0｜招募与签约

**时间：正式体验开始前**

完成：

- 企业基本条件确认
- 老板初步需求沟通
- 30天体验内容说明
- 99元体验服务费规则确认（按D02第八节）
- 数据与隐私授权
- 建立企业档案编号
- 预约首次访谈

内部必须记录客户来源。

例如：

- 熟人介绍
- 商协会
- 企业转介绍
- 主动拜访
- 线上内容
- 其他渠道

---

### 阶段1｜首次问诊与建档

**建议：第1–3天**

安排60–90分钟企业经营访谈。

重点了解：

- 企业如何赚钱
- 主要客户
- 产品与服务
- 获客和销售渠道
- 成本与回款
- 最近主要经营变化
- 老板当前最关心的问题
- 未来90天目标
- 现有经营数据

访谈完成后，由AI辅助整理：

**《企业经营基础档案 V1.0》**

同时形成：

**《首次定向资料清单》**

原则上只索取最重要的几项资料。

---

### 阶段2｜首次经营体检

**建议：第3–7天**

根据行业和资料条件选择：

- 简明体检
- 行业专业体检
- 约定范围内的重点问题分析

顾问审核AI分析与计算结果。

形成：

- 老板版经营体检报告
- 内部分析底稿
- 主要问题、风险和机会
- 经营基线V1.0
- 经营监测清单V1.0
- 30天行动计划

正式服务以访谈完成并确认资料截止条件后，原则上5个工作日内出具初版。

如果企业迟迟没有提供关键资料，应明确数据截止日，交付有限资料版本，不无限期等待。

安排一次必要的结果解读与校准。

**这一阶段真正的目标：**

让老板产生一个明确感受：

> 你们基本理解了我的生意，而且发现了值得进一步关注的事情。

---

### 阶段3｜持续服务开始

**建议：第8–14天**

开始围绕企业实际问题提供持续服务。

至少完成：

- 第一次经营简报
- 已确定行动事项的进度跟进
- 企业适配的外部信息扫描
- 必要的经营问答
- 数据来源和监测方式确认

特别注意：

不要求每家企业每天都产生新的提醒。

没有重要变化时，可以正常汇总，不制造异常。

---

### 阶段4｜验证实际使用价值

**建议：第15–21天**

这个阶段不再把报告作为服务中心。

重点观察老板真正如何使用服务。

例如：

- 主动提出了什么问题？
- 哪些提醒认真看了？
- 哪份材料实际用了？
- 哪条政策或商机进一步核实了？
- 哪个经营问题开始处理了？
- 有没有主动介绍别人来咨询？

对企业明显不使用的服务，应主动了解原因。

可能是：

- 内容没有价值
- 呈现方式不合适
- 发送太频繁
- 老板太忙
- 数据太难提供
- 之前的判断不准确

根据原因调整，而不是继续机械输出。

---

### 阶段5｜30天复盘与转化

**建议：第22–30天**

重点完成：

**《30天经营健康管理服务回顾》**

内容包括：

- 当初老板最关心什么
- 这30天实际做了什么
- 发现并跟进了哪些问题
- 有没有具体改善
- 有哪些新的风险或机会
- 哪些事项仍未解决
- 后续最值得持续关注什么

最后安排一次正式沟通。

询问：

> 如果以后每个月继续有人帮你看经营、提醒问题、处理事情，你愿不愿意继续使用？

根据实际需求推荐：

- 基础版199元/月
- 标准版399元/月
- 顾问版1299元/月起

不预设所有客户都适合标准版。

客户选择正式服务、暂缓、拒绝或要求专项服务，都应记录实际原因。

# 五、试运营交付节奏

| 时间  | 客户主要感知       | 内部主要工作       |
| --- | ------------ | ------------ |
| 第1周 | 有人真正开始了解我的企业 | 访谈、建档、体检、校准  |
| 第2周 | 有人在帮我持续关注经营  | 简报、提醒、行动跟进   |
| 第3周 | 遇到问题可以找他们处理  | 问诊、资源对接、价值验证 |
| 第4周 | 看得见一个月实际做了什么 | 复盘、价值总结、续费沟通 |

由于每家企业启动时间可能不同，应按企业自身试运营日程安排简报。

首次体检期间也可以提供适当的简短进展反馈。

# 六、需要重点验证的四项核心服务

## 6.1 看经营

检验：

- 企业是否愿意定期提供经营数据
- 能否形成有依据的经营判断
- 能否识别老板之前忽略的变化
- 是否能帮助推动实际行动

不是简单统计生成了几张图表。

## 6.2 找机会

检验：

- 是否能够识别真正符合企业条件的政策
- 是否能够找到有需求的客户或合作线索
- 企业是否愿意进一步核实机会
- 是否形成有效对接

对机会应区分：

信息线索、资格初筛、已验证机会和实际成交。

不能把普通信息推送记录成已创造商业价值。

## 6.3 处理事

检验：

- 老板是否主动提出经营问题
- 哪些问题最常出现
- AI是否能完成多数初稿工作
- 顾问需要多少人工时间
- 客户是否实际使用产出

记录问题解决情况，而不只记录回复次数。

## 6.4 找资源

检验：

- 企业是否存在真实资源需求
- 是否能够找到合适的合作机构
- 企业是否愿意接受推荐
- 是否形成有效沟通和后续处理

资源撮合需要取得相关方同意。

不能为了提高转化而随意转发客户经营信息。

# 七、试运营期间的工作量边界

这部分直接决定未来能否盈利。

首次建档和首次体检通常比日常维护更耗费人工，应当单独统计。

## 7.1 建议记录的人工环节

| 环节      | 需要记录的时间      |
| ------- | ------------ |
| 客户招募与沟通 | 获客人工时间       |
| 首次访谈    | 访谈实际时间       |
| 建档与资料整理 | 人工整理时间       |
| 首次体检    | 数据清洗、分析、审核时间 |
| 报告解读    | 顾问沟通时间       |
| 每周服务    | 周报审核、提醒、跟进时间 |
| 经营问诊    | 每次处理时间       |
| 材料支持    | 制作及修改时间      |
| 资源对接    | 筛选与沟通时间      |
| 月末复盘    | 复盘和转化沟通时间    |

AI运行时间与顾问人工时间分开记录。

试运营额外赠送的服务必须单独标记。

## 7.2 试运营工时假设

以下数字仅供设计资源容量，不代表已经验证的实际成本。

- 首次建档与体检：每家约3–6小时人工
- 后续三周服务：每家累计约2–5小时人工
- 30天复盘与续费沟通：每家约0.5–1.5小时人工

整体试运营，每家可能需要约5.5–12.5小时人工，不含获客、重大专项及异常数据修复。

实际工时必须用试点记录替代估算。

如果8家企业同时参与，核心交付可能需要约44–100小时人工，加上获客、沟通和平台建设工作。

因此建议：

**分批启动，每批2–3家，避免集中交付。**

## 7.3 与正式会员成本分开

试运营阶段第一次深度了解企业，可以视为客户获取和建档投入的一部分。

但不能因为试运营愿意超配，就把超配内容默认变成399元会员的永久权益。

特别需要观察：

如果正式399元标准版客户每个月大量使用问诊、材料、数据分析和人工沟通，现有定价可能无法覆盖成本。

这不是靠简单提高AI使用率就一定能够解决的。

试点必须验证正式续费阶段的单位经济模型，并据此修订B01和B02。

# 八、最小运营工具与工作台

第一阶段不要求先完成一个复杂SaaS平台。

可优先采用：

**微信/企业微信 + WorkBuddy + 结构化表格 + 文件空间 + 人工审核。**

## 8.1 最小数据结构

### 企业表

记录企业ID、行业、联系人、服务状态、套餐意向、试点起止日期等。

### 企业档案表

记录经营模型、老板主诉、重点客户与渠道、关键事项、数据可用情况。

### 服务记录表

记录服务类型、内容、负责人、处理状态、人工时间、客户反馈。

### 问题与机会表

记录发现时间、事实、证据、影响、建议、处理进度。

### 经营监测表

记录指标、来源、更新频率、触发条件、最近检查时间。

### 行动事项表

记录企业确认的待办、负责人、到期时间、结果。

### 商业验证表

记录获客来源、实际付费、转化结果、续费意愿和拒绝原因。

## 8.2 WorkBuddy优先承担

- 整理访谈
- 更新企业档案草稿
- 信息检索和初筛
- 生成定向资料清单
- 周报与月报初稿
- 服务记录归档
- 经营行动跟进提醒
- 运营数据汇总

关键经营数字使用可靠计算程序。

重要经营建议经过顾问审核。

不以个人微信数据库抓取、未经授权的自动发送或完整平台接口接入作为试运营启动前提。

# 九、试运营内部经营驾驶舱

驾驶舱先服务于运营人员，而不是让老板另外安装复杂系统。

首期建议只显示以下六组指标。

| 模块   | 关注内容                |
| ---- | ------------------- |
| 客户进度 | 已招募、已访谈、已体检、服务中、已结束 |
| 服务交付 | 本周应完成与逾期事项          |
| 服务使用 | 问诊、材料、简报、提醒、资源推荐    |
| 服务成本 | 各客户累计人工工时、AI使用及其他成本 |
| 客户反馈 | 看过什么、实际用了什么、是否有价值   |
| 商业转化 | 意向客户、正式签约、选择套餐、拒绝原因 |

先用表格或轻量后台实现。

若试点证明多客户管理确有明显效率问题，再决定开发专用仪表台。

# 十、试运营核心指标

所有指标应区分：

**实际结果**与**内部验证目标**。

以下目标为建议的初始测试门槛，不代表行业经验数据。

## 10.1 招募与参与

- 正式体验企业：目标5–10家
- 已完成首次访谈比例
- 有明确老板主诉的比例
- 愿意提供至少一种经营资料的比例
- 完成首次报告及解读的比例

## 10.2 服务交付

- 首次体检完成时间
- 应交付简报完成比例
- 重大事项提醒是否及时
- 数据与结论是否出现明显错误
- 企业是否理解重要建议

## 10.3 价值验证

重点观察：

- 企业是否实际采用至少一项建议
- 企业是否主动提出后续问题
- 是否产生可确认的经营改善
- 是否发现有价值的风险或机会
- 是否形成有效资源连接

没有可量化财务收益也可以记录其他可验证的价值，例如避免遗漏重要期限、完善经营数据或推进原本拖延的事项。

## 10.4 商业验证

最重要的是：

**正式付费转化率。**

同时记录：

- 选择哪个套餐
- 为什么选择
- 为什么不续费
- 是否愿意介绍其他客户
- 是否产生合理的专项服务需求
- 每家客户实际服务成本

# 十一、30天结束时的决策标准

不要因为客户口头说“不错”，就宣布商业模式验证成功。

建议按照四个方面复盘。

## A｜需求成立了吗？

是否存在明确的付费需求？

如果老板只想要免费体检，但不愿持续付费，就说明一次性报告有价值，不一定说明长期会员服务成立。

## B｜服务成立了吗？

客户是否真正使用了持续提醒、问诊、资源连接或经营分析？

如果几乎全部价值集中在首次体检，应该考虑调整产品结构。

## C｜交付成立了吗？

人工时间是否可控？

数据是否能持续获得？

AI是否真正减少了重复劳动？

如果每家企业都需要大量手工整理和专项咨询，则需要缩小范围、提高价格或加强工具能力。

## D｜商业模式成立了吗？

正式会员收入是否有可能覆盖：

- 顾问人工
- AI与软件
- 客户获取
- 日常管理
- 其他必要成本

需要区分一次性初诊投入与长期维护成本。

### 初步推进判断

**继续扩大试点：**

出现真实付费转化、持续使用行为，并且服务成本存在收敛路径。

**调整后再试：**

客户认可首次体检，但持续服务使用较低，或人工成本明显偏高。

**暂不扩大：**

主要价值依赖免费超配、低价重度咨询，且看不到合理的单位经济模型。

首批样本规模很小，不以某一个固定百分比作为单独判定依据，应结合用户行为和成本分析。

# 十二、试运营结束后必须形成的内部成果

### 1. 《首批试点企业分析汇总》

不同企业及行业的实际需求和反馈。

### 2. 《服务使用与成本分析》

哪些服务真正被使用，哪些服务最耗费人工。

### 3. 《AI自动化效果评估》

哪些工作确实节省了时间，哪些环节仍需人工。

### 4. 《会员转化与定价复盘》

199/399/1299元套餐是否需要调整。

### 5. 《MVP开发优先级修订》

哪些功能在试点中被反复需要，哪些原计划功能暂不开发。

### 6. 《下一轮试运营或正式运营决策》

明确继续、调整还是暂停扩张。

# 十三、执行中的三个红线

**第一，不为了成功案例制造经营成果。**

尚未落实的商业机会不能算成交，未经验证的预计收益不能算客户节省的成本。

**第二，不为了试点体验无限提供人工服务。**

可以主动多做一步，但必须记录工作量，明确超配性质。

**第三，不为快速开发牺牲企业数据安全。**

企业资料按授权范围使用，正式建议经顾问审核，关键操作保留可追溯记录。

# 十四、30天试运营的最终目标

30天结束后，我们至少应该知道：

- 哪些中小企业真正愿意购买服务
- 老板愿意为什么付费
- 哪些行业更适合优先经营
- 哪些服务最容易体现价值
- 哪些服务能被AI稳定辅助
- 哪些工作过于依赖人工
- 长期服务成本到底有多高
- 现有定价与套餐边界是否合理
- 哪些开发功能值得优先投入

**首批试点不以企业数量最大化为目标，而以尽快找到可持续、可复制的服务模型为目标。**
