# D07｜真实客户项目分仓、证据与交付版本管理规范 V0.1

**性质**：内部试运营规范（非客户授权、非法律意见）  
**适用**：首次访谈、公开情报研究、客户建议书、后续伴随式支持  
**关联**：B03-1首次信息采集规范、D04客户服务运营SOP、D06免费M-L0预服务SOP、G12资料处理合规复核、仓库`.gitignore`

## 1. 分仓边界

`companyhealth`为通用产品、方法、SOP与模板仓库。未经专门脱敏审阅及适当授权，**不提交可识别的客户案例、客户经营档案、原始访谈、聊天记录、个人资料、平台后台数据、合同、财务资料、截图或完整调研交付**。仓库即使改成私有，也不等同于取得客户资料处理或第三方云存储授权。

客户资料应使用**独立、受控的客户资料空间**：每家客户唯一编号、最小访问权限、来源登记、资料保留/退出安排；如拟使用第三方Git托管，先核实实际仓库可见性、受邀人员、提供者服务条款、客户授权及敏感程度。高敏感原始材料优先限制在单独受控存储，不自动进入任何Git仓库。外部服务方和AI处理前另行确认处理范围。

公开仓库只允许：空白模板、无识别信息的示例、通用方法、经适当审阅与授权的匿名化经验。`.gitignore`是防误传辅助手段，不代替审查。

## 2. 推荐的客户工作空间结构（仅模板）

```text
<客户专属受控空间>/
  00_总览与权限/README.md
  01_企业基本档案/企业画像.md
  02_访谈与沟通/纪要与决策日志.md
  03_外部经营情报/研究任务书与证据索引.md
  04_服务成果/对外建议书版本目录.md
  05_跟进与反馈/问题机会台账.md
  99_原始材料索引/原件存放说明.md
```

`99_原始材料索引`只保存定位与授权状态，**不要求上传原件**。合同、原始个人聊天、财务报表、原始录音/转写应根据权限与必要性放入独立受控存储；不得以“方便备份”为理由复制到公开Git或未经审查的第三方环境。

## 3. 资料和判断的最低元数据

每项重要资料至少记录：`客户编号`、`资料ID`、`日期/版本`、`来源类型`、`来源原件定位`、`是否公开`、`权限/授权状态`、`覆盖期`、`使用范围`、`审阅者`、`下次复核条件`。

事实标签统一采用：
- **P（公开证据）**：可核验的官方、商家或平台公开内容；记录链接及检索日期。
- **C（客户口述）**：经营方表达或计划；仅作口述，不写成已签约、已成交或已执行。
- **U（用户/服务方观察）**：观察及页面截图；不推出后台销量、投资回报或公司登记结论。
- **H（工作假设/建议）**：模型/顾问推断，须列出验证条件。
- **V（已核实）**：通过可靠原始材料核验的具体事实；标注核验范围，不泛化。

例：公开团购页面“展示售出数量”是**截图观察**，不代表全渠道销量；经营者称“合作团队已在推进”是**口述/转述**，不等于签约或完工。

## 4. 首次接触到持续服务的版本路径

1. **初次接触**：最小企业画像及对方关注点，确认身份和允许使用信息的范围。
2. **公开研究**：保留研究任务书、数据来源、统计口径、观察时间和无法核验事项；市场整体规模不得推算单店收益。
3. **外部观察稿**：每一项指出的机会同时注明“已有公开证据—对企业的关联—待核问题”；经人工复核才可发送。
4. **客户沟通校正**：将客户反馈记录为新的`C`类证据，标明日期和参与者，不静默覆盖历史档案。
5. **版本更新**：每份交付有`版本/状态（草稿、送审、已对外提交、作废）/变更说明/审阅记录`；保留前版供追溯。
6. **小任务体验**：记范围、投入、交付、客户反馈，不因“提出建议”就当作已验收成果。
7. **终止和资料处置**：根据授权、合同及D06/G12的保留要求处理，不能保证Git历史内已上传文件可被彻底抹除。

## 5. PR/合并检查清单

- [ ] 目标仓库的可见性、实际协作者和客户资料边界已核实。
- [ ] 没有个人联系方式、原始对话/音频、内部账目、敏感合同等非必要原件。
- [ ] 没有把访谈推测、市场推断或截图展示数写成已核实企业事实。
- [ ] 对外数据有来源、检索时间、指标口径；不引用不可复核的AI来源标记作唯一出处。
- [ ] 文档标明版本、状态、适用范围和主要变化。
- [ ] 对外服务承诺不超出已授权和可履约范围。
- [ ] 至少一名责任人完成内容与隐私检查，再合并主分支。

**当前原则**：内部客户项目仍在未取得适当授权时，可以继续进行不需敏感资料的公开市场研究和方法准备；不得以仓库合并代替客户授权、正式签约或服务验收。
