# D07｜原“真实客户项目分仓、证据与交付版本管理规范 V0.1”废止记录

**状态：原 D07 强制分仓规则自本次修订起停止作为企业级档案编写的限制。**  
**适用仓库：** `companyhealth`（当前 GitHub Public 公开仓库）  
**本轮决策：** 仓库可记录真实企业的完整**企业级**背景、工商公开资料、企业项目需求、顾问分析、首诊报告、执行计划和版本记录。不再以“可识别真实企业”为由禁止企业级档案入仓。

## 必须区分的存储边界

允许在公开仓库保存企业级信息，不等于已取得公开披露一切第三方资料的合法权限。下列内容除非依法具备明确处理及公开依据并完成逐项核验，否则不进入公开仓库：

- 普通客户姓名与联系方式、会员完整名单、病史、健康指标、就诊记录、医疗系统原始档案或医保结算明细；
- 员工私人联系方式、身份证件、银行卡、账号密码、密钥及其他无关个人资料；
- 未经许可的录音/转写、非公开合同、企业经营后台原始导出、第三方保密资料；
- 可导致对个人敏感状况推断的信息，或未经核实的涉嫌违法、违约结论。

## 企业级资料的使用规则

1. 企业真实名称和公开工商信息可以记录；说明来源为用户截图、口述、公开可核实来源或已核实资料。
2. 企业经营背景、估算规模及咨询项目历史可写入，但必须标明“用户转述/观察/工作假设/核实事实”，避免把未核实信息写成审计结论。
3. 详细首诊报告与执行计划允许入仓，敏感个体内容以必要的聚合或匿名表达替代。
4. 保留报告版本、修改时间、证据类型、待核问题、校准过程与客户反馈，不静默将工作假设改为事实。
5. 正式对外提交、收费、资料上传第三方AI、客户联系等业务行为仍必须依据实际授权、合同和法律条件执行；一次仓库变更不构成授权。
6. 所有 Pull Request 仍审查个人信息、经营敏感信息、资料真实性和可公开披露范围；Public Git 历史可能长期被复制或保留。

## 旧规则替换说明

原 D07 中“一律不提交可识别真实企业案例及完整报告”“必须另建客户专属空间”的**内部普遍禁令废止**，可以按企业需求自愿另外使用受控空间，不再是强制的仓库工作规则。

原 D07 的资料来源标注、判断和证据分离、版本留痕、客户同意与第三方信息保护等原则继续作为通用真实性与安全要求，与 B03、B03-1、D04、G03/G05/G10、CLAUDE.md 等并行适用。

**声明：** 此修订是项目方仓库政策，不改变个人信息保护、医疗数据管理、保密合同和其他适用法律义务。
