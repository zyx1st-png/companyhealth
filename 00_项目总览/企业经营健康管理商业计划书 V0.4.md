# 一、执行摘要

## 1.1 我们要解决什么问题

许多中小企业已经拥有各种经营工具：

- 微信、Excel和各类办公软件
- 收银、进销存和财务系统
- 美团、抖音等经营平台
- 代账、财税、法律等外部服务
- 各种通用AI助手

企业真正可能缺少的，并不是更多工具，而是一个能够长期理解其经营状况、综合处理信息并持续跟进问题的外部服务角色。

例如：

一家商贸企业知道最近销售还不错，却没有发现应收增长速度已经超过销售增长。

一家餐饮企业知道抖音团购卖得多，却没有算清活动实际留下多少经营贡献。

一家小型服务企业经常错过值得关注的政策信息，或者遇到管理问题时不知道应该找谁解决。

这些需求不一定需要大型咨询项目，但也未必能通过一次AI问答得到解决。

## 1.2 我们提供什么

企业经营健康管理借鉴个人健康管理和家庭医生模式，为企业建立长期经营服务关系：

**建档 → 体检 → 监测 → 问诊 → 资源转介 → 行动跟进 → 周期复盘。**

其服务能力集中于四个方面：

**看经营：** 关注企业重要经营变化，分析问题和潜在风险。

**找机会：** 按企业条件筛选政策、市场、客户、供应链和合作机会。

**处理事：** 协助完成常见经营分析、材料、方案和问题研究。

**找资源：** 推荐并协调适合的专业机构、供应商和合作伙伴。

## 1.3 产品如何交付

客户主要通过熟悉的微信或企业微信交流，不需要为使用服务而更换原有管理系统。

后台采用：

**企业独立经营档案 + 共享公共信息处理 + 行业指标计算 + AI分析生成 + 人工审核 + 服务任务跟进。**

常规任务尽可能批量处理。

重要经营判断、客户沟通和高风险事项由人工承担。

6. 高级专项能否以较高客单价成交，并在可承受工时内完成验收。

**项目第一阶段的成功，不是完成系统开发或签约大量企业，而是证明少量真实客户愿意持续付费，且交付成本存在可控的下降路径。**

# 二、市场机会与需求逻辑

## 2.1 核心需求假设

当前项目提出一个需要市场验证的判断：

> **中小企业可能存在介于“自己使用免费工具”和“聘请专业经营顾问”之间的长期经营支持需求。**

这类企业未必需要全职经营分析人员。

但在经营过程中，经常存在重复出现的轻量化问题：

- 销售、客户或渠道发生变化
- 库存、应收与资金占用
- 促销、定价和活动判断
- 企业管理与日常经营材料
- 政策与行业机会
- 上下游资源对接
- 重要经营事项跟进

这些问题具有一定连续性，但未必足以单独形成高价咨询项目。

## 2.2 为什么现有工具不能完全解决

现有工具已经能够解决相当多的单点问题。

通用AI可以分析资料、生成文本和提供思路。

收银、财务和平台系统可以输出经营报表。

财税、法律等专业机构能够处理各自领域的问题。

因此，项目不能将竞争优势建立在“其他产品不会生成周报”上。

拟探索的差异化价值是：

**跨经营场景理解 + 持续服务关系 + 重要判断审核 + 实际行动跟进。**

例如：

发现销售下降只是第一步。

进一步核实是哪些客户、产品或渠道造成变化，协助企业安排后续行动，并在下一周期根据结果更新判断，才是持续服务希望创造的价值。

## 2.3 主要购买动机

初期重点验证四类付费动机。

| 购买动机 | 老板希望得到什么             |
| ---- | -------------------- |
| 节省时间 | 有人处理值得做但不值得专门雇人的经营琐事 |
| 降低遗漏 | 重要问题、机会及日期有人持续关注     |
| 获得判断 | 遇到经营问题，有人帮助分析和提出下一步  |
| 找到资源 | 不熟悉专业领域时，能够得到可信转介及跟进 |

这些是产品假设，并非已经证明的购买规律。

## 2.4 不采用虚高市场规模估算

目前不使用：

**全国中小企业数量 × 会员费**

来代表项目实际市场规模。

因为并非所有经营主体都具有相同需求、预算、付费意愿和数据配合能力。

创业初期更有意义的是测算：

**实际可触达企业 → 愿意沟通 → 付费体验 → 正式转化 → 持续续费。**

当地市场规模及可获得市场，需要通过真实客户调研和销售漏斗逐步建立。

# 三、目标客户与市场进入策略

## 3.1 第一类：具有一定经营规模的中小企业

初期最值得验证的核心客户。

典型特征：

- 已经持续经营
- 有多个业务环节或一定数量的员工
- 老板亲自承担较多经营管理事务
- 拥有部分经营数据
- 没有专职经营分析团队
- 存在需要持续跟进的经营问题

这类客户可能更容易感受到经营健康管理的价值。

## 3.2 第二类：成长型及多门店企业

例如：

- 多门店餐饮与零售企业
- 多业务线商贸企业
- 正在扩张的服务企业
- 项目型企业

可能需要：

- 跨业务经营分析
- 渠道、门店或项目比较
- 经营管理流程改进
- 较复杂的经营决策支持

此类客户可探索顾问版及专项服务。

但较复杂的系统集成和大型咨询项目不能直接纳入低价会员权益。

## 3.3 第三类：商协会和企业服务机构

包括：

- 商协会
- 产业园区
- 企业服务机构
- 专业服务合作方

需要区分三种关系：

**机构推荐，企业购买。**

**机构组织服务活动，项目方参与。**

**机构直接采购企业服务。**

三者对应不同的付费主体、合同、责任和数据权限。

目前以合作机制研究与自愿转介为主要方向，机构采购不计入确定收入。

## 3.4 首期优先行业

根据现有行业模板能力与初期客户接触条件，建议优先验证：

**商贸批发及经销。**

重点是客户变化、应收账款、库存、商品贡献和资金周转。

**餐饮与多门店经营。**

重点是销售变化、堂食与平台收入、套餐贡献、主要费用和单店模型。

其他工程、制造和生活服务企业，可以先通过通用经营体检底座提供适当服务。

不宜一开始就投入开发六个成熟行业系统。

## 3.5 初期客户选择原则

优先选择：

**有真实问题、愿意沟通、能够合理交付、有付费可能的企业。**

不单纯按企业规模和营业额筛选。

# 四、产品价值与服务体系

## 4.1 一套完整的经营服务闭环

\<escape>客户接触\</escape>\
→ **首次经营访谈**\
→ **企业经营档案**\
→ **首次经营体检**\
→ **经营雷达**\
→ **持续简报、提醒与问诊**\
→ **行动跟进**\
→ **周期复盘**\
→ **续费或专项服务**

其中，第一次经营体检负责建立认知。

后续持续服务负责不断更新认知并产生长期价值。

## 4.2 看经营

根据企业实际资料和授权条件，分析：

- 销售及收入变化
- 客户与渠道变化
- 产品和服务经营情况
- 应收和库存
- 主要经营成本
- 组织与执行事项
- 经营风险

不是每家企业都需要完整的财务分析。

也不是所有企业都具备周度或实时数据。

监测频率应由数据来源和服务约定决定。

## 4.3 找机会

关注与企业实际条件匹配的：

- 政策和补贴
- 招投标
- 潜在客户
- 市场与渠道变化
- 供应链合作
- 本地商业资源
- 企业数字化改善机会

信息处理必须区分：

**普通线索、待核实机会、已验证适配条件和实际商业成果。**

不将信息匹配直接等同于订单、补贴或经营收益。

## 4.4 处理事

通过微信接收企业需求。

例如：

- 协助分析经营数据
- 判断一个活动方案
- 整理经营汇报材料
- 研究渠道变化
- 准备客户拜访方案
- 协助处理常见经营问题

服务范围按套餐与具体约定执行。

大型专项项目单独立项。

## 4.5 找资源

遇到超出项目直接能力的需求时，协助企业：

**明确问题 → 选择候选服务商 → 自愿对接 → 跟进结果。**

涉及法律、财税、审计及其他专业资质事项，由合适的专业机构承担其专业服务责任。

# 五、首次经营体检：建立持续服务的基础

## 5.1 核心方法

首次体检采用已有B03定义的：

**“1 + 3 + 1”经营体检模型。**

即：

**一个经营模型。**

理解客户、产品、渠道、成交、交付、收入、成本和回款。

**三张地图。**

识别当前重要的问题、风险与机会。

**一套经营雷达。**

确定未来持续关注什么、数据来自哪里、多久更新、什么变化值得提醒。

## 5.2 行业专业化

采用：

**通用经营体检底座 + 行业模块 + 企业个性化问题 + 分层报告。**

餐饮与商贸企业虽然使用相同的经营理解方法，但指标和重点分析不同。

例如：

餐饮企业应重点区分团购销售、核销、平台结算和真实经营贡献。

商贸企业应重点识别客户销售、回款、账龄和库存之间的关系。

## 5.3 对老板的交付

优先使用简单、明确、可行动的表达。

通常包括：

- 一句话经营判断
- 1–3项重点发现
- 当前主要问题与机会
- 30天行动计划
- 后续监测事项

深入的数据、证据和计算过程放在内部底稿或专项附件中。

**不使用缺乏依据的统一经营健康总分，也不在数据不足时生成虚假精确的结论。**

## 5.4 首次体检不是终点

首次体检成功的标志不仅是报告交付。

还应完成：

- 与企业负责人校准分析
- 确定优先行动
- 形成经营基线
- 建立监测事项
- 进入后续持续服务

这也是项目与单次报告销售的主要区别。

**拥有一个长期了解企业、能够参与重要经营讨论的外部顾问。**

1299元是参考起价。

应根据企业复杂程度、会议、分析及材料需求明确范围。

## 6.5 年度服务

基础版保留：

**1980元/年。**

标准版和顾问版不宜在验证初期通过大幅折扣促进年付。

年度预收款形成未来交付义务，不能简单视为已实现利润。

## 6.6 当前不采用的旧产品口径

V0.3不将以下设计作为默认执行基线：

- 面向所有企业的完整免费体检
- 499元深度顾问版
- 普遍不限次的咨询服务
- 未经明确范围确认的低价次卡
- 将政策申报成功分成视为常规收入
- 把高工作量专项服务纳入基础会员

上述模式可以在未来根据真实需求重新研究，但不得与现行套餐混用。

# 七、旧99元30天体验设计（历史废止章节，禁止用于新客）

## 7.1 试运营的意义

30天体验不是为了证明AI能生成漂亮报告。

真正需要验证的是：

- 企业是否愿意提供必要信息
- 老板能否感受到首次体检的价值
- 持续服务是否产生真实使用
- AI能否减少顾问重复劳动
- 企业是否愿意购买长期服务

## 7.2 对外交付

按照约定范围，包括：

1. 一次经营访谈
2. 一份适配行业及数据条件的首次体检报告
3. 企业经营档案和监测事项
4. 一份30天重点行动计划
5. 约定的每周简报
6. 重要风险、机会与事项提醒
7. 体验范围内的经营问题协助
8. 期末复盘及正式会员建议

## 7.3 收费规则

**体验费：99元／30天。**

支付体验费不代表购买长期会员。

项目方完成约定服务后，不因客户不续费而无条件退款。

如项目方未履行约定或出现法律规定的其他情形，依合同及适用规则处理。

正式购买会员时，99元全额抵扣。

不自动续费。

## 7.4 必须防止重复计算收入

例如客户体验后购买399元标准版。

客户累计支付：

**99元体验费 + 300元首月尾款 = 399元。**

不能将其计算为498元。

具体收入确认、抵扣和税务处理根据合同及适用规则执行。

## 7.5 控制首次体验的人工容量

D01初始情景估计：

**每家30天体验需要约5.5–12.5小时人工。**

该估计不含获客、大型专项及复杂异常处理。

因此首批5–10家应分批启动，每批约2–3家。

AI改善后可以争取降低人工工时，但必须用实测结果替代估算。

# 九、AI驱动的规模化服务机制

## 9.1 项目的关键效率假设

传统咨询通常按照企业分别开展大量工作。

本项目希望形成：

**一套服务底层，同时支持多家企业的差异化交付。**

企业各自的经营资料、授权、判断与报告保持独立。

共享的是：

- 公共政策和行业信息处理成果
- 行业指标及计算程序
- 经营分析方法
- 任务和审核流程
- 报告结构
- 运营统计能力

## 9.2 五层服务能力

### 第一层｜企业经营档案

记录：

- 企业经营模型
- 当前重要问题
- 关键指标
- 重要客户和关系
- 行动事项
- 服务历史
- 已授权的数据及其边界

### 第二层｜共享信息引擎

统一采集、核实和整理：

- 政策
- 公开招投标
- 行业变化
- 公开商业信息
- 可公开分享的资源信息

再根据企业条件进行个性化匹配。

### 第三层｜计算与规则引擎

负责：

- 数据导入与映射
- 指标计算
- 日期比较
- 异常规则
- 来源记录
- 数据质量检查

重要数字优先由确定性程序计算。

### 第四层｜AI生成与分析

生成：

- 企业资料摘要
- 经营分析初稿
- 周报与月报初稿
- 问题假设
- 定向资料清单
- 行动建议草稿

### 第五层｜人工例外与审核

处理：

- 数据异常
- 来源冲突
- 重要经营判断
- 客户问诊
- 高风险建议
- 正式交付
- 资源协调

## 9.3 批量运营模式

传统模式：

**企业A完整处理 → 企业B完整处理 → 企业C完整处理。**

拟采用模式：

**共享信息处理 → 多企业任务调度 → 分企业数据计算 → 分企业生成 → 集中审核 → 分别交付。**

真正的效率指标不是AI生成数量，而是：

**每增加一家企业，需要增加多少人工处理时间。**

## 9.4 AI不能替代的工作

包括：

- 经营主诉确认
- 重要商业判断
- 真实关系建立
- 重大事项沟通
- 专业责任承担
- 必要的面对面服务
- 客户服务质量审核

因此不能预设所有服务都能实现极低人工成本。

# 十、技术与产品实施路线

## 10.1 初期技术原则

**先做可用的内部运营系统，不急于建设完整SaaS。**

初期工具可以采用：

- 微信／企业微信
- WorkBuddy
- Python或其他可靠计算程序
- 结构化表格与轻量数据库
- 独立客户资料空间
- 人工审核和发送机制

具体技术选型通过小范围验证确定。

## 10.2 第一阶段优先实现

**企业档案与授权记录。**

**客户服务工单。**

**首次访谈整理。**

**行业经营数据计算。**

**经营简报生成。**

**行动跟进提醒。**

**人工审核与交付记录。**

**服务工时统计。**

## 10.3 WorkBuddy的角色

主要承担AI辅助工作流、材料处理和内容草稿等适合的任务。

是否采用WorkBuddy负责统一调度，需要结合实际接口、稳定性、费用和权限条件验证。

不能因为工具可以执行单次Agent任务，就默认具备多企业、多人、高可靠性的后台运营能力。

## 10.4 经营驾驶舱

第一阶段重点是内部运营驾驶舱。

包括：

- 待响应客户
- 待审核报告
- 到期服务事项
- 监测异常
- 客户使用情况
- 实际服务工时
- 续费进度
- 销售漏斗
- 现金收支

驾驶舱应当帮助运营者决定下一步做什么。

不优先开发供客户观看的大型图表系统。

## 10.5 技术阶段

| 阶段 | 核心系统        |
| -- | ----------- |
| T0 | 最小服务工作台     |
| T1 | 多企业批量交付与审核  |
| T2 | 多人协作和权限管理   |
| T3 | 行业模块及机构服务能力 |
| T4 | 独立SaaS可行性研究 |

每一阶段均需要真实需求和质量验证。

不因为完成T0就认定项目已经实现T4。

# 十一、商业模式与收入结构

## 11.1 收入引擎一：会员订阅

收入来自：

- 199元基础版
- 399元标准版
- 1299元起顾问版

其核心作用是：

**形成经常性收入与长期企业服务关系。**

如果AI规模化能力足够强，会员业务自身可能具有合理现金贡献。

不能预先判断会员只是低利润获客工具。

## 11.2 收入引擎二：高级专项服务

收入来自 B08 的 P01–P05 高级专项，以及会员专项简析。

其核心作用是：

**以较高客单价解决明确、重要的经营问题，并检验客户为“结果明确的专业判断”付费的意愿。**

专项业务可能带来更高客单价，也可能消耗更多人工。

必须按项目独立核算：售前工时、交付工时、返工、外包、差旅和实际毛利。

## 11.3 渠道与合作

商协会、企业服务机构及专业伙伴主要承担：

- 需求发现
- 自愿转介
- 专业资源协同
- 联合服务活动

未来可能产生机构采购收入，但现阶段不纳入确定收入。

## 11.4 两种收入不相互依赖

不能预设：

每个会员都会购买专项服务。

也不能预设：

只有产生专项项目，会员业务才有商业意义。

未来根据真实数据决定业务结构。

# 十二、获客与客户转化

## 12.1 主要获客渠道

初期采用四个方向。

**直接关系网络：**

既有企业经营者、熟人介绍和真实业务关系。

**协会与商会：**

专业共建、企业需求交流、自愿转介。

**专业服务合作：**

财税、法律、企业软件及其他服务机构。

**专业内容与案例：**

通过经营问题分析展示专业能力。

## 12.2 不采用大规模广告和扫街作为首期主线

原因是：

第一阶段尚未知道哪些客户最愿意付费，哪种价值表达最有效。

在商业验证之前，扩大流量投入可能只会加速消耗交付容量。

## 12.3 试点销售漏斗

D02设定的初始规划情景：

| 阶段   |    参考数量 |
| ---- | ------: |
| 潜在线索 |  40–60家 |
| 有效沟通 |  20–30家 |
| 深入介绍 |  12–16家 |
| 付费体验 |   5–10家 |
| 正式购买 | 按真实结果记录 |
| 持续续费 |  后续按月观察 |

以上仅作为工作计划。

不得视为已验证的转化率。

## 12.4 续费依靠什么

不能只依靠首次报告质量。

每月应让客户看见：

- 实际完成哪些服务
- 发现哪些值得关注的变化
- 哪些问题获得了处理
- 哪些行动已经推进
- 哪些机会值得进一步研究
- 下一月为什么仍值得继续服务

**续费的核心是持续价值，不是反复销售。**

# 十三、与商协会的合作战略

## 13.1 合作定位

项目发起人当前选择：

**参与协会企业经营服务体系共建，同时保持独立创业主体、产品和商业经营。**

这属于项目内部战略，并不意味着已经获得协会正式任命或合同确认。

## 13.2 协会层面的价值

围绕：

**企业走访 → 需求识别 → 分类分流 → 资源匹配 → 服务反馈 → 需求更新**

建立更加连续的企业服务机制。

协会可以重点发挥：

- 企业组织能力
- 企业间供需匹配
- 公共会员服务
- 专业服务资源协调

## 13.3 独立商业项目的价值

项目方重点负责自愿购买服务企业的：

- 首次经营体检
- 企业经营档案
- 经营监测和问诊
- 个性化经营分析
- 专项服务
- 持续行动跟进

## 13.4 第一阶段合作方式

建议先选择：

**2–3家自愿企业，开展约30天的协会需求闭环验证。**

重点检验：

- 需求能否被准确识别
- 能否分类给合适的服务方
- 是否形成真实跟进
- 企业是否需要长期经营支持

该试点不默认包含企业完整的30天商业体检及会员服务。

希望购买完整体验的企业，应在具备合法收费条件后另行签订服务协议。

## 13.5 内部资源边界

首轮协会共建投入暂按：

**每周2–4小时。**

该数字是创业者内部时间预算，并非已对外承诺的服务时长。

协会职务、长期工作范围、人员支持、知识产权、收费合作及利益冲突处理，需要后续协商。

## 13.6 不应作出的假设

不能认为：

- 协会所述企业数量均为有效会员
- 所有会员均可被直接营销
- 协会一定采购系统
- 专业负责人岗位已经确定
- 协会合作必然带来大量付费客户

协会合作的商业价值，需要通过实际有效需求和自愿成交验证。

# 十四、经营成本与盈利模型

## 14.1 必须区分三套模型

**现金经营模型**

评价真实收款能否覆盖实际现金支出。

**人工容量模型**

评价创始人能否按服务承诺持续交付。

**组织复制模型**

评价加入运营人员、顾问与技术维护成本后，业务是否仍有扩张价值。

这三套模型不能互相代替。

## 14.2 初期现金预算

当前内部规划：

**月固定经营现金预算约1298元。**

主要覆盖部分工具、存储、通信、交通、记账及基础运营等支出。

这一数字属于规划假设，并不涵盖所有未来费用。

创始人初期暂不领取固定工资。

但创始人投入的时间必须单独记录，以判断服务容量和长期经济可行性。

## 14.3 单客户新增现金成本假设

| 套餐  | 月度假设增量现金成本 |
| --- | ---------: |
| 基础版 |         5元 |
| 标准版 |        10元 |
| 顾问版 |        30元 |

这些是为情景测算预留的费用，并非已经获得的真实平台成本数据。

如已包含在固定订阅费用中，不能重复扣减。

## 14.4 稳定会员规模情景

暂按以下假设客户组合：

**20%基础版、70%标准版、10%顾问版。**

| 指标           |       20家 |        30家 |        50家 |
| ------------ | --------: | ---------: | ---------: |
| 基础版          |        4家 |         6家 |        10家 |

# 十五、服务人工容量与真正的规模化约束

## 15.1 创始人工作时间

当前内部预算：

**每天约6小时，每月按22个工作日约132小时。**

| 工作类别        |      月度预算 |
| ----------- | --------: |
| 协会共建        |      12小时 |
| 获客和销售       |      20小时 |
| AI工作流和产品改进  |      20小时 |
| 日常运营管理      |      15小时 |
| **客户与会员服务** |  **65小时** |
| **合计**      | **132小时** |

建议在65小时服务时间内预留约20%缓冲。

即常规工作暂尽量安排在约52小时以内。

## 15.2 服务工时模型

**月服务总工时 = 共享服务工时 + 存量客户个性化工时 + 新客户建档工时 + 异常及额外服务工时。**

其中定期批量任务的共享工时，不应简单按客户数重复累加。

但实际会议、问诊、个别审核与协调时间必须真实记录。

## 15.3 不同规模的人工压力

C02 V1.1的初始情景：

| 正式会员 |     乐观效率 |     基准效率 |  人工压力情景 |
| ---- | -------: | -------: | ------: |
| 20家  | 30.4小时/月 | 45.4小时/月 |  74小时/月 |
| 30家  | 39.6小时/月 | 62.1小时/月 | 105小时/月 |
| 50家  |   58小时/月 | 95.5小时/月 | 167小时/月 |

以上包含假设的每月12小时共享工作，但不含新客户首次建档和尚未估算的异常工作。

## 15.4 对30家规模的判断

30家稳定会员在基准效率下约需要62.1小时服务时间。

这已接近单人65小时服务预算。

因此不能将30家视为必然能够轻松交付的单人规模。

## 15.5 对50家规模的判断

50家只有接近乐观效率时，月工时才可能接近现有预算。

但当前套餐包含：

- 季度面对面复诊
- 月度经营会议
- 个性化问诊
- 中等材料
- 顾问审核
- 资源协调

这些工作具有实际人工下限。

因此50家只能作为远期效率压力测试，不作为已经具备的服务能力。

## 15.6 更重要的限制是高峰响应

月度人工时间够，不代表工作日1小时或2小时内一定能够响应。

需要同时监控：

- 月度总人工
- 临时问诊高峰
- 未回复积压
- 服务响应达标率
- 重要报告审核
- 逾期任务
- 客户集中度

不能简单使用平均工时决定接单规模。

# 十六、MVP开发与技术验证

## 16.1 第一阶段不建设完整平台

目标是先跑通：

**收件 → 资料识别 → 数据分析 → 生成初稿 → 人工审核 → 交付 → 跟进记录。**

客户端继续使用微信。

后台先采用轻量化结构和现有工具。

## 16.2 MVP核心要求

- 企业独立档案与编号
- 授权与数据来源登记
- 资料导入和分类
- 可追溯的指标计算
- 行业模板
- 周报生成
- 人工审核与交付记录
- 服务工单及待办
- 工时统计

首期不依赖：

- 自动读取全部微信聊天
- 自动向外部客户发送消息
- 完整ERP接口
- 复杂多Agent平台
- 大型客户自助前台
- 跨企业私有数据共享

## 16.3 技术验证应与商业验证分开

技术试验T01计划通过：

**E01：** 公共政策及机会信息批量匹配。

**E02：** 20家模拟企业个性化周报批量生成。

**E03：** 同行业多企业经营数据计算复用。

**E04：** 首次经营体检自动化辅助。

以上属于拟开展的实验，不代表已经通过。

## 16.4 重要技术验收

首先必须做到：

- 企业数据不混淆
- 关键数字可追溯
- 缺失数据不能被虚构
- 重要经营建议可由人工审核和否决
- 重要内容不未经批准发送
- 任务执行和错误可追踪

其次再评价：

- 批量人工时间
- 相对逐家AI辅助的节省程度
- 首次配置成本
- 后续维护成本
- 工具调用与扩容费用

不能通过省略质量审核来制造效率提升。

# 十七、90天商业验证计划

## 17.1 第一个阶段：建立最小交付闭环

主要工作：

- 完善体验服务协议
- 确定真实收费及授权流程
- 完成最小内部工作台
- 选取首批2–3家企业
- 完成首次访谈与经营体检
- 测量真实人工工时

验收重点：

是否能够可靠完成基本服务。

## 17.2 第二个阶段：形成真实持续服务

主要工作：

- 分批扩展到5–10家体验企业
- 按企业周期交付简报与提醒
- 记录问诊和材料实际使用
- 开始收集首次体验反馈
- 验证批量任务和行业计算
- 测量重要服务响应

验收重点：

**企业是否真的使用持续服务，而不是只需要第一次报告。**

## 17.3 第三个阶段：商业复盘

主要工作：

- 完成已到期客户的30天复盘
- 向适配客户提供正式套餐
- 记录实际签约与收款
- 记录未购买原因
- 统计全部人工投入
- 分析AI效率和服务质量
- 判断下一轮开发和招募重点

首轮可以将**至少3家真实正式购买**作为内部参考目标之一。

但样本规模很小，不能仅凭该数字认定商业模式已经成熟。

## 17.4 GO / ADJUST / NO-GO决策

### GO｜继续小范围推进

条件包括：

- 出现真实正式付费
- 客户实际使用持续服务
- 服务交付可靠
- 有可观察的AI效率改善
- 人工和现金成本有合理控制路径

### ADJUST｜调整后再验证

例如：

- 老板喜欢首次体检但不愿续费
- 399元权益消耗过多人工
- 数据更新太困难
- AI报告需要大量修改
- 协会合作积极但真实付费有限

应调整客群、套餐、流程或技术。

### NO-GO｜暂停扩大投入

例如：

- 长期缺乏真实付费意愿
- 服务价值依赖大规模免费超配
- 必要人工显著超出合理承受范围
- 无法保障重要数据安全
- 关键服务质量问题无法控制

不宜通过招聘、广告或平台开发掩盖基本商业问题。

## 17.5 高级专项线的并行验证

按 B08 第十章：

| 时间 | 目标 |
| --- | --- |
| 第1–14天 | 完成 P01/P03/P04 产品卡与范围确认单；准备两个明确标注“模拟”的演示样例；整理报价、合同与数据授权流程 |
| 第15–45天 | 8–12条有具体问题的推荐线索，5–8次有效初筛，至少3份正式报价，争取1–2单真实付费 |
| 第46–90天 | 至少1单从签约到验收的完整闭环；记录是否产生后续实施、AI工作流或顾问需求 |

## 17.6 双线时间分配规则

两条线共用每月约65小时的客户服务预算。为避免互相挤占，建议：

- **同一时间最多1个在途高级专项**（P01 约18–35小时）。
- 会员线**每批2–3家体验企业**（每家30天约5.5–12.5小时）。
- 示例：1批3家体验（约27小时）+ 1个P01（约25小时）≈ 52小时，处于常规排期参考线附近。
- 新专项若会使当月排期超过约52小时，顺延开工或调整体验批次，**不压缩已承诺的会员服务**。

## 17.7 90天主线裁决

90天结束时，两条线分别按 F01 第十三章与 B08 第十章做 GO / ADJUST / NO-GO 判断，再比较：

| 比较维度 | 看什么 |
| --- | --- |
| 真实成交 | 实际收款，而非口头意向 |
| 每小时现金贡献 | 实际收款 ÷ 实际投入工时（含售前） |
| 获客难度 | 从线索到成交的周期与次数 |
| 持续性 | 会员续费、专项复购或转化 |
| 可复制性 | 能否标准化、能否交给系统或他人 |

| 会员线 | 专项线 | 建议 |
| --- | --- | --- |
| GO | GO | 双线保留；按每小时贡献分配下一阶段时间 |
| GO | ADJUST/NO-GO | 会员为主线，专项退回为会员增值服务 |
| ADJUST/NO-GO | GO | 专项为主线，会员降为诊断后的轻量持续服务 |
| 均未通过 | 均未通过 | 暂停扩张，重新定位客群与产品 |

裁决结果写入商业计划书下一版本。

# 十八、发展路线与组织复制

## 18.1 P0｜最小服务验证

**2–5家体验企业。**

创始人主导服务，AI辅助后台。

目标是完整交付和建立初步证据。

## 18.2 P1｜首批正式经营

**5–10家体验及少量正式会员。**

目标是真实购买、正式转化和服务工时验证。

## 18.3 P2｜多客户稳定运营

**8–15家正式会员参考区间。**

目标是批量任务、客户数据更新与服务质量。

根据实际瓶颈考虑兼职运营支持。

## 18.4 P3｜组织复制验证

**20–30家正式会员参考区间。**

可能形成：

**创始人／核心顾问 + 运营支持 + AI系统 + 专业合作网络。**

重点是让部分工作可以交接，同时减少创始人重复劳动。

## 18.5 P4｜组织化与区域扩展

**30–50家及以上。**

仅在商业、技术和组织分工已经取得实际证据后推进。

重点验证：

- 第二位顾问能否独立交付
- 服务质量能否保持一致
- 新增人员成本是否合理
- 跨地区服务是否经济
- 客户获取是否可以复制

不提前采用加盟、分公司和大规模销售团队作为基本发展方式。

# 十九、竞争优势与长期壁垒

## 19.1 当前拟建立的竞争优势

**第一：持续经营认知。**

根据授权长期理解企业经营模型、历史变化和未完成事项。

**第二：跨业务场景分析。**

不局限于某一个经营平台。

**第三：人工判断与服务责任。**

AI提供辅助，顾问负责重要审核、解释及服务跟进。

**第四：行业专业方法。**

通过餐饮、商贸等行业指标及计算程序提高分析针对性。

**第五：可靠的资源协同。**

对接合适的专业人员和机构。

## 19.2 真正有望积累的壁垒

不是某一款大模型、提示词或办公Agent。

而是：

**经过验证的行业经营知识 + 持续客户服务记录 + 标准化交付流程 + 质量审核体系 + 真实专业资源网络。**

客户私有经营数据并不因为进入服务系统就成为项目方可自由使用的资产。

长期竞争能力应主要来自合规形成的经营方法、质量能力和服务信任。

## 19.3 当前不宣称已经形成壁垒

目前尚未完成：

- 多客户长期续费验证
- 大规模AI交付验证
- 多顾问复制
- 成熟行业数据库
- 可对外商业化的软件平台

这些属于未来需要建设和验证的能力。

# 二十、数据安全与服务责任

## 20.1 最小必要原则

企业无需一次性提供全部经营数据。

首先通过访谈了解问题。

然后说明需要哪些资料、用于什么目的，并在符合授权与适用规则的情况下处理。

## 20.2 企业数据独立管理

每家企业建立独立档案及数据空间。

不跨企业共享原始经营数据。

不默认将客户信息接入协会或合作机构系统。

## 20.3 AI处理边界

应明确：

- AI参与的服务环节
- 使用目的及数据范围
- 工具服务商条件
- 必要的第三方处理安排
- 数据访问和权限
- 保留、退出及删除规则

在相应合法处理条件不清楚时，先使用模拟或经过适当处理的数据测试。

## 20.4 人工审核

关键数字应来自可靠计算。

重大经营判断、专业解释和重要对外材料应经过相应人工审核。

AI不得直接代表律师、会计师、税务专业机构等出具需要相应资格或专业责任的正式意见。

## 20.5 客户退出

按照合同及适用规则处理：

- 停止服务任务
- 未完成事项交接
- 数据返还或删除
- 必须保留记录的依法保存
- 撤销不再需要的权限

不预先承诺不具备执行条件的绝对删除期限。

# 二十三、未来商业形态的选择

本项目未来可能发展出四种不同结果。

## A｜AI驱动的企业会员服务公司

如果订阅、续费和低人工交付同时成立，长期会员可以成为主营业务。

## B｜经营咨询与专项服务公司

如果企业主要愿意为具体经营诊断和项目付费，而不重视订阅，则可以提高专项服务比重。

## C｜机构企业服务解决方案

如果商协会、园区等机构具备明确采购预算，可以探索机构层面的标准化企业服务。

## D｜企业服务软件与工作流平台

如果内部服务系统成熟，并且外部机构或企业愿意为软件独立付费，可进一步研究SaaS模式。

目前不要求四种模式同时成立。

**第一阶段优先验证A，并观察B和C；D作为技术积累后的可选方向。**

# 二十四、项目需要怎样的投入

## 24.1 当前启动模式

以创始人主导和轻资产投入为原则。

主要投入：

- 创始人时间
- AI和办公工具
- 基础数据与文件处理
- 必要的客户拜访
- 合同及数据保护准备
- 最小系统开发和维护

## 24.2 暂不作为启动前提

- 大型办公室
- 全职顾问团队
- 大规模专用服务器
- 独立SaaS平台
- 多地区分支机构
- 大额广告投放

## 24.3 如需新增资金

应首先用于解除经过实际验证的瓶颈。

例如：

- 数据安全和可靠性
- 真实服务流程自动化
- 必要的客户获取
- 高重复任务的兼职运营
- 合同和专业合规支持

不以展示公司规模为投资目标。

## 24.4 当前融资定位

由于尚缺少真实收入、续费和单位经济数据，现阶段不建议依据大规模会员预测提出确定的融资估值或资金回报承诺。

更适合优先通过小规模真实经营获得商业证据，再确定是否需要外部投资。

# 二十五、未来12个月的战略目标

建议用三个能力目标替代单纯的客户数量目标。

## 目标一：商业成立

找到真实、重复的购买理由。

出现持续付费和明确客户使用行为。

## 目标二：交付成立

建立可重复的行业经营体检和周期服务流程。

能够控制必要人工时间、响应与质量。

## 目标三：复制成立

找到能够批量处理的任务。

识别哪些工作能够交给系统或运营支持人员。

在条件成熟时验证第二个服务人员的独立交付能力。

**不将12个月达到30家或50家正式会员设定为没有条件限制的必须完成目标。**

客户规模只能在商业、交付和资金能力允许时扩大。

# 二十六、最终商业判断

企业经营健康管理的商业机会，并不简单来自AI降低写报告的成本。

其更有潜力的逻辑是：

**大量中小企业有持续产生、但单次价值不一定很高的经营支持需求。**

这些需求分散、重复、跨领域，并且需要连续的企业上下文。

传统高成本顾问模式未必适合低价高频服务。

纯自助软件又不一定能承担理解企业、核实判断、协调资源和跟进结果的完整工作。

本项目希望建立一种中间形态：

> **用AI和程序降低重复工作，用顾问承担重要判断，用标准流程管理持续服务，用专业网络处理复杂问题。**

如果这套模式能够真实成立，它将同时具备：

**长期客户关系、可重复服务能力、较低新增现金成本和逐步组织复制的可能性。**

但现阶段只能确认：

项目已经形成比较完整的产品和商业设计。

尚不能确认：

客户愿意长期购买，也不能确认AI已经支持相应的规模化服务能力。

因此未来最重要的不是继续论证商业模式在理论上有多大空间。

而是通过实际交付回答：

**客户为什么愿意持续付钱？**

**每家客户需要增加多少真实工作量？**

**哪些任务真的可以共享和自动化？**

**这种模式能否在加入员工和其他组织成本后继续成立？**

**能否逐步摆脱对创始人个人工作的完全依赖？**

最终愿景是：

> **让中小企业不用专门建立完整的经营分析团队，也能够拥有一个长期了解企业、持续关注问题、提供经营支持并协助寻找资源的外部经营服务体系。**

项目的价值不以AI模型数量、生成报告数量或签约会员数量衡量。

而以：

**客户实际获得的帮助、持续付费意愿、交付质量以及能够长期维持的服务成本**衡量。

# 附录B｜商业模式验证证据等级

建议未来版本采用统一的四类状态。

**已确认：** 创业者已经确定的产品、原则或内部资源预算。

**已完成：** 有实际交付或实验记录支持的成果。

**待验证：** 有合理设计和假设，但尚无充分真实运营证据。

**未确定：** 需要进一步协商、调查或决策的事项。

这四种状态应在未来的商业计划书、财务测算及合作文件中保持一致。
