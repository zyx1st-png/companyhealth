# 企业经营健康管理 MVP 最小开发需求文档

Oct 2, 2026 · @zhangyuxin

## 一、MVP 目标

MVP 要在 30 天内，为 5–10 家试点企业跑通“收件 → 分析 → 人工审核 → 发送 → 反馈”闭环，开发周期控制在 2 周以内，现金投入控制在 1 万元以内。

本期要验证的核心假设：**一位顾问借助 AI，每周能以不超过 1–2 小时的人工，稳定服务 5–10 家企业，并且企业愿意持续提供数据、阅读报告、付费续约。**

系统只需回答四个问题：

1. 企业是否愿意每周发送经营数据？
2. 自动生成的周报经人工修改后，是否达到可发送的质量？
3. 每家企业每周实际占用多少人工时间？
4. 老板是否阅读周报、主动提问或提出增值需求？

本期不追求全自动、不追求平台化，所有对外消息由顾问确认后发送。

## 二、范围

本期只做顾问自己使用的后台工具，客户端完全沿用微信，不开发任何面向客户的界面。

| 本期做 | 本期不做（后续迭代） |
| --- | --- |
| 监控本地文件夹，自动接收客户发来的文件 | 自动向客户发送消息 |
| 按约定识别文件所属企业 | 解密微信数据库、Computer Use 操作微信 |
| Excel、CSV 与美团、抖音导出数据的解析 | 对接 POS、ERP、财务系统 API |
| 按行业模板计算指标、识别异常 | 会话内容存档、实时回复 |
| 大模型生成周报、月报初稿 | 客户自助查询界面或小程序 |
| 发送队列与人工审核后台 | 跨企业横向对比 |
| 修改原因记录与周度统计 | 资源撮合、专业服务转介系统 |
| 外部雷达：政策与补贴信息的人工整理加 AI 摘要 | 外部信息的自动爬取 |

行业范围：首期只支持 1–2 个行业模板，建议从商贸和本地生活服务中选择，由试点企业构成最终决定。

## 三、用户角色与核心流程

系统有三个角色：老板只在微信里收发，系统自动完成从接收到初稿的全部工作，顾问负责审核、发送和处理例外。

文件名无法识别时进入“待归类”，由顾问指定所属企业。顾问每次审核的动作和修改原因进入反馈统计，用来持续优化提示词和行业模板。

## 四、功能需求

共 9 个模块，P0 必须在试点第一天前完成，P1 可在试点期间补上。

| 模块 | 功能要点 | 优先级 |
| --- | --- | --- |
| M1 企业档案 | 后台建档：企业编码、简称、行业、联系人、12 项档案字段；绑定行业指标模板；记录服务事件 | P0 |
| M2 文件接收 | 监控微信文件接收目录；按文件名规则“企业简称\_数据类型\_日期”识别企业；识别失败进入“待归类”由顾问手动指定；按哈希值去重；复制到企业专属目录 | P0 |
| M3 数据解析 | 读取 Excel、CSV；内置美团、抖音导出格式的字段映射；字段映射可配置；解析失败时生成提示进入队列 | P0 |
| M3+ 图片识别 | 截图、照片中的表格用视觉模型识别，结果须人工核对 | P1 |
| M4 指标与异常 | 按行业模板计算指标与环比；规则阈值判断异常（如环比变化超过设定比例、回款逾期天数）；保存指标历史 | P0 |
| M5 报告生成 | 周报初稿：数字由代码填入固定位置，大模型只写解读与建议；输出为可直接粘贴进微信的文本 | P0 |
| M5+ 月报与图表 | 月度体检报告、趋势图、经营状态标记（稳定／需关注／优先处理／有机会／信息不足，不折算总分，见 T02 §20.1）；PPT 可先用 WorkBuddy 手工生成 | P1 |
| M6 发送队列 | 列表展示收件企业（醒目大字）、消息类型、优先级、生成时间、状态；操作：一键复制正文、打开附件、标记已发送、修改后发送、退回重做；修改或退回时必选原因 | P0 |
| M7 反馈统计 | 每周汇总：各类消息修改率、错误类型分布、平均处理时长、每家企业人工时间 | P0 |
| M8 外部雷达 | 顾问录入政策或补贴条目，AI 按企业行业和档案匹配，生成摘要进入队列 | P1 |
| M9 互动与线索 | 手动记录老板的提问、需求和承诺事项；增值服务线索打标签；待办到期提醒 | P1 |

修改原因的固定选项：数字错误、遗漏重点、建议空泛、语气不当、发错对象风险、其他。

## 五、数据结构

共 6 张表，全部以企业编码作为隔离键，任何查询都必须带企业编码。

| 表 | 主要字段 | 说明 |
| --- | --- | --- |
| companies 企业档案 | company\_id、简称、全称、行业、联系人、微信备注名、行业模板 ID、档案 JSON、状态、建档日期 | 档案 12 项字段先存为 JSON，后续再拆表 |
| files 文件 | file\_id、company\_id、原文件名、存储路径、文件哈希、数据类型、接收时间、解析状态 | 原始文件只读保存，不做修改 |
| metrics 指标 | company\_id、指标编码、统计周期、数值、来源 file\_id、计算时间 | 每次计算都可追溯到源文件 |
| alerts 异常 | alert\_id、company\_id、指标编码、规则、实际值、阈值、级别、状态 | 级别分紧急、一般、提示 |
| queue 发送队列 | msg\_id、company\_id、消息类型、优先级、正文初稿、正文终稿、附件路径、状态、生成时间、发送时间 | 状态：待审、已发送、退回、作废 |
| feedback 反馈 | msg\_id、处理动作、修改原因、处理耗时（秒）、处理时间 | 由队列操作自动写入 |

行业指标模板单独存为配置文件（YAML），包括指标定义、计算公式、异常阈值，修改模板不需要改代码。

## 六、技术方案与选型

整套系统用 Python 单机运行在一台专用电脑上，不需要服务器和公网地址。该电脑登录一个专门的业务微信号。

| 环节 | 选型 | 理由 |
| --- | --- | --- |
| 运行环境 | 一台常开的 Windows 小主机，安装 PC 微信 | 微信文件落地在本机，无需解密数据库 |
| 文件监控 | Python watchdog | 监听微信文件接收目录，新文件触发处理 |
| 数据解析 | pandas、openpyxl | 处理 Excel 和 CSV 的成熟方案 |
| 存储 | SQLite，文件按企业分目录存放 | 零运维，便于备份，日后可迁移到 MySQL |
| 指标计算 | Python 代码加 YAML 行业模板 | 数字只由代码计算，保证准确 |
| 文本生成 | 国内大模型 API | 只输入计算好的指标和档案摘要，数据不出境 |
| 队列后台 | Streamlit | 一个人一两天能搭出可用界面，本机浏览器访问 |
| 定时任务 | APScheduler | 每周一早上自动生成周报初稿 |
| 临时任务 | WorkBuddy（手工使用） | PPT、海报、临时分析，不进入自动流程 |
| 备份 | 每日加密打包，存本地硬盘加网盘 | 防止单机故障丢数据 |

大模型调用规则：只传入当期指标、异常列表和档案摘要，不传入原始文件；提示词按消息类型分别维护，版本号写入队列记录，便于对比修改率。

## 七、非功能需求

最高优先级是“不发错对象、不算错数字”，其次才是效率。

- **数据隔离：** 每家企业独立目录；数据库查询强制带企业编码；生成报告时只加载该企业的数据；队列界面收件企业用大字和颜色区分。
- **防发错：** 标记“已发送”前须再次确认收件企业名称；同一时间只允许展开一条待审消息。
- **数字准确：** 报告中的所有数字由代码填入；大模型输出中如出现模板以外的数字，自动标红提示人工核对。
- **安全：** 专用电脑开机密码加硬盘加密；大模型 API 不上传原始文件；与每家试点企业签署数据授权和保密协议；企业退出时 7 天内删除其全部数据。
- **可靠性：** 程序开机自启；每天早上自检微信是否在线、监控是否运行、昨日文件是否处理，异常时提醒顾问。
- **性能：** 单个文件从接收到进入队列不超过 5 分钟；周报初稿每周一 9:00 前全部生成。

## 八、验收标准与试点指标

开发验收看系统能否稳定跑通闭环，试点验收看商业假设是否成立。

**开发验收（试点开始前）**

- [ ] 用 3 份真实格式的样例文件，从放入目录到生成队列消息全程无人工干预
- [ ] 文件名不规范时能进入“待归类”，不会归错企业
- [ ] 周报中所有数字与手工计算结果一致
- [ ] 队列的复制、标记、退回、修改原因记录均可用
- [ ] 断电重启后程序自动恢复，未处理文件不丢失

**试点指标（30 天）**

| 指标 | 目标值 |
| --- | --- |
| 每周按时发送数据的企业比例 | ≥ 60% |
| 周报修改率（第 4 周） | ≤ 30% |
| 每家企业每周人工时间 | ≤ 15 分钟 |
| 发错对象次数 | 0 |
| 老板主动提问或提需求的企业数 | ≥ 3 家 |
| 试点后愿意付费的企业数 | ≥ 2 家 |

## 十、待确认事项与后续迭代

开发启动前需要确认以下事项：

- [ ] 首期行业：商贸、本地生活服务，还是按试点企业实际构成决定
- [ ] 当前版本 PC 微信的文件接收目录位置，以及大文件是否自动下载
- [ ] 选用哪家国内大模型 API，以及单家企业每月调用成本
- [ ] 开发方式：自己用 AI 编程工具开发，还是外包
- [ ] 数据授权与保密协议文本

后续迭代路线：

1. **试点后（10–15 家）：** 某类消息连续数周修改率很低时，改为自动发送；开通企业微信会话内容存档，取消手动转发和文件命名约定。
2. **规模化（30 家以上）：** 迁移到云服务器和 MySQL；接入 POS、进销存等系统；在获得授权的前提下做跨企业匿名对比。
