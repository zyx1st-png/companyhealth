## 一、核心商业判断

企业经营健康管理希望建立一种不同于传统咨询公司的经营模式：

> **用一套可以持续复用的AI服务系统，为多家企业提供个性化经营支持，由少量人工完成关键判断、沟通与复杂事项处理。**

其收入来源主要是长期会员订阅，并辅以专项经营咨询、数字化服务和资源协同。

在这一模式下，不应简单假设：

每增加一家客户，就需要增加一份完整的顾问工作量。

相反，可能存在三类规模效应：

**第一，信息共享。** 一次政策检索或行业研究可以服务多家适配企业。

**第二，能力复用。** 指标计算程序、行业分析模板和报告生成流程可以重复使用。

**第三，集中管理。** 多家企业的监测、提醒、报告及服务状态可以在统一工作台处理。

因此，项目应重点验证：

**新增一家会员带来的收入，是否远高于为其新增的现金支出和人工工作量。**

这是本项目规模化潜力的核心。

## 二、成本模型的重新定义

### 2.1 现金成本

当前创业初期，创始人不领取固定工资，不雇用全职员工。

因此实际现金成本主要包括：

- AI和软件订阅
- 云存储及数据处理
- 通信
- 客户拜访交通
- 推广及销售材料
- 记账及基本财税服务
- 银行及其他必要运营费用
- 实际发生的专业外包
- 税费及其他实际支出

根据H02《单客户经济模型与90天预算 V1.0.xlsx》的重建预算，月度现金经营预算暂按（旧D03-A V1.2原件不在现行仓库中，不能把重建分项视为原始凭证）：

**1298元/月。**

该金额是规划值，不是已经发生的真实费用。

### 2.2 创始人时间

创始人的时间不计入当前现金利润，但必须记录。

原因不是它在财务上已经发生支出，而是：

**即使不支付工资，创始人一天能够处理的工作仍有上限。**

因此时间应首先作为产能指标，而非当前现金成本。

### 2.3 未来雇员成本

招聘员工后的人工成本属于下一阶段组织复制模型。

在验证早期不使用假定员工工资否定当前创业模式。

当项目准备增加运营人员、顾问或技术人员时，再对未来工资、管理成本和交付能力进行专项测算。

## 三、三套独立评价模型

| 模型   | 核心公式          | 用途         |
| ---- | ------------- | ---------- |
| 现金盈利 | 实际收入－实际现金支出   | 判断项目能否持续经营 |
| 人工容量 | 可用服务工时－实际服务工时 | 判断能服务多少企业  |
| 组织复制 | 收入－工具、员工及其他成本 | 判断未来能否扩张团队 |

三个模型分别评价，不再混用。

**当前优先验证前两项。**

## 四、AI批量交付的基本架构

建议将服务划分为四个层次。

### 第一层：共享信息处理

一次收集、多企业复用。

包括：

- 政策及公开信息检索
- 行业资讯
- 本地商业动态
- 招投标等机会线索
- 行业研究
- 企业资源信息

处理流程：

**收集 → 去重 → 核实 → 结构化 → 匹配企业 → 生成个性化内容**

注意：共享的是公开信息处理成果，不是不同企业的私有经营数据。

### 第二层：标准化企业数据处理

不同客户采用相同的指标定义和计算规则。

例如：

- 营业额变化
- 客户收入结构
- 应收账龄
- 库存周转
- 主要渠道贡献
- 门店经营变化

对已经完成格式映射的数据，可以批量运行计算程序。

AI主要负责解释和生成初稿。

关键数字由确定性的程序计算。

### 第三层：企业专属AI生成

依据每家企业的：

- 经营档案
- 行业模板
- 最新数据
- 历史问题
- 行动事项
- 服务权益

生成个性化：

- 经营周报
- 月度简析
- 机会提醒
- 风险提示
- 客户问题回复草稿
- 材料初稿
- 行动跟进建议

这里虽然可以批量执行，企业上下文仍需要分别隔离。

### 第四层：人工例外处理

人工重点负责：

- 首次经营访谈
- 复杂数据异常
- 重要经营判断
- 高风险信息核实
- 客户沟通与关系维护
- 专业资源协调
- 关键报告审核
- 重大事项处理

目标是使大量常规任务不需要人工逐条从头执行。

但不能以减少人工为由取消必要的质量审核。

## 五、从逐家交付转向批次交付

传统模式：

**客户A全流程 → 客户B全流程 → 客户C全流程。**

拟采用的模式：

**所有客户更新资料 → 统一运行任务 → 分别形成结果 → 集中审核 → 分别交付。**

### 举例：20家企业的周报

不需要手工从头写20份周报。

可以设计为：

1. 系统读取20家企业各自的授权数据和服务记录。
2. 批量计算各企业的指标变化。
3. 将同一批已经核实的外部信息与企业档案进行匹配。
4. 分别生成20份简报初稿。
5. 自动筛出数据异常、证据不足和重要变化。
6. 顾问重点审核异常和重要建议。
7. 按客户身份分别发送，保存交付记录。

20份周报并不等于20倍完整编写时间。

实际人工时间取决于：

- 数据标准化程度
- 企业之间的差异
- AI初稿质量
- 错误与异常数量
- 审核要求

因此，系统设计应主动追求批量交付。

## 六、现金成本结构

采用两类成本。

### 6.1 固定现金预算

暂按：

**1298元/月。**

包含现有D03-A规划中的AI、工具、存储、通信、交通、记账等项目。

### 6.2 边际现金成本

只有当新增企业确实带来额外支出时，才计入新增客户成本。

不能把已经包含在AI订阅内的费用，再按照客户数重复扣除。

为了进行情景分析，暂设以下额外成本。

| 套餐       | 假设每月新增现金成本 |
| -------- | ---------: |
| 基础版199元  |       5元/家 |
| 标准版399元  |      10元/家 |
| 顾问版1299元 |      30元/家 |

这里的费用只是模型假设，用于容纳额外计算、文件处理等可能的实际支出。

不是已经核实的AI平台单客户收费。

实际费用如果已经包含在固定订阅内，应记为零；若超出固定额度，则按实际额外支出计算。

### 6.3 阶梯式系统费用

AI和云服务不一定能够在原有固定订阅下无限支持客户增长。

因此增加一种情景假设：

| 规模    | 固定预算以外的扩容费用 |
| ----- | ----------: |
| 20家客户 |          0元 |
| 30家客户 |      600元/月 |
| 50家客户 |     1500元/月 |

上述数字用于压力测算，并非真实服务商报价。

实际扩容成本需根据工具订阅、调用量、存储及运行情况重新核实。

## 十、最关键的变量：人工干预密度

不能把AI任务数量等同于人工工作量。

建议定义：

**单客户月度人工干预时间**

包括：

- 审核
- 个性化修改
- 实际问诊
- 客户沟通
- 问题协调
- 约定会议
- 例外处理

不包含纯AI等待或自动运行时间。

另外，将公共信息处理和批量任务管理记录为：

**共享服务工时。**

因此：

**月度服务总工时 = 共享服务工时 + 各客户个性化人工工时 + 新客户建档工时。**

共享服务工时不会因为客户数量增加而必然同比增长，但也不能认定永远不变。

## 十一、三种人工效率情景

假设每月共享批量服务工作为12小时。

对已完成建档的稳定会员，设定三种不同效率情景。

| 套餐  | 乐观：高度自动化 | 基准：部分人工 | 压力：人工需求偏高 |
| --- | -------: | ------: | --------: |
| 基础版 |    0.3小时 |   0.6小时 |       1小时 |
| 标准版 |    0.8小时 |   1.5小时 |       3小时 |
| 顾问版 |      3小时 |     5小时 |       8小时 |

上述数字均是待验证假设，不代表当前系统已经达到相应效率。

特别需要注意：

按照现行B02，标准版包含季度面对面复诊，顾问版包含月度经营会议和较多材料支持。

因此乐观情景要求极高的AI自动化和工作组织效率。面对面时间、必要沟通、出行以及履约审核不能被AI直接替代。

若按现有服务承诺无法达到这些人工时间，就必须使用实际工时，而不能靠模型假设压低。

## 十二、不同客户规模下的人工容量

继续采用：

20%基础版、70%标准版、10%顾问版。

包括每月12小时共享批量工作。

| 正式会员规模 |   乐观情景 |   基准情景 |  压力情景 |
| ------ | -----: | -----: | ----: |
| 20家    | 30.4小时 | 45.4小时 |  74小时 |
| 30家    | 39.6小时 | 62.1小时 | 105小时 |
| 50家    |   58小时 | 95.5小时 | 167小时 |

以上不包含新增客户的首次建档，也不包含创业者用于获客、开发、协会合作及内部管理的时间。

### 创始人可用时间

目前规划：

**6小时/天 × 22天 = 132小时/月。**

内部可暂按以下方式分配：

| 工作方向       |   月度预留时间 |
| ---------- | -------: |
| 协会公益共建     |     12小时 |
| 客户开发与销售    |     20小时 |
| 产品及AI工作流改进 |     20小时 |
| 一般运营与管理    |     15小时 |
| **剩余服务时间** | **65小时** |

上述分配只是容量预算，实际可以调整。

在65小时服务预算下：

- 20家客户：乐观和基准情景可以容纳。
- 30家客户：基准情景已经接近容量上限。
- 50家客户：只有接近乐观效率时，才可能在现有服务预算内运行。

此外，实际服务请求可能集中发生，月度工时充足也不代表一定能满足1小时或2小时首次响应承诺。

**结论：现金收入可以较快增长，但单人运营规模最终受到人工干预密度和响应要求约束。**

## 十三、首次体检与新客户建档

首次体检具有不同于正常会员维护的成本结构。

B03、B03-1目前要求：

- 初始经营访谈
- 经营模型梳理
- 基础资料盘点
- 问题、风险和机会分析
- 报告生成和审核
- 经营雷达设置
- 行动计划
- 结果解读和校准

因此即使AI能够完成大量整理、计算和初稿，也仍存在必要的客户沟通与审核工作。

### 建议保留三个工时口径

**旧流程基准：**

D01原估计每家30天体验5.5–12.5小时。

**新AI流程目标：**

尽量通过统一数据结构、自动整理、行业模板和报告生成降低人工时间。

**实际交付结果：**

以真实客户的人工计时为准。

现阶段不把旧流程上限当作不可突破的交付成本，也不直接宣称AI已经将人工压缩到1小时以内。

### 容量计算必须考虑新客户

例如：

30家稳定会员，在基准效率下需要62.1小时/月。

如果同月新增2家企业，每家首次建档及体检额外占用3小时，那么总计约68.1小时。

这已经超出前述65小时服务预算。

所以，稳定存量客户规模与每月新增客户容量必须分别规划。

## 十四、免费M-L0获客与直接月费转化（2026-10-13替代版）

**取消新客99元收费体验与抵扣，不产生任何免费期现金收入。** 旧版本的99元付款转正模型不再有效；原有会员稳态工时、服务权益和表格测算，亦必须基于新的B06高频日常事务配额重算。至少区分免费获客与初次交付分钟、正式会员例行周报/问诊分钟、客户主动日常快办/定制任务分钟、审核/返工、共享信息核验、公益协会时间以及P专项时间。

- 正式购买会员时全额抵扣
- 不自动续费
- 依法应处理的履约、退款等问题仍按协议与适用规则执行

在当前现金口径下：

如果没有额外现金支出，99元体验可以贡献一定现金收入。

但体验期会占用创始人的服务容量。

因此关键问题不再是：

**“99元能不能覆盖创始人80元/小时的假定工资？”**

而是：

**“以AI辅助方式完成一位体验客户，需要占用多少稀缺人工时间，能否形成有价值的长期客户关系？”**

对于转正客户，99元全额抵扣首月会员费，因此仍不可重复计算收入。

对于未转正客户，是否值得交付完整体验，取决于实际现金支出、投入时间、客户反馈及获客价值。

---

## 十五、专项服务仍然重要，但不是唯一利润来源

修正V1.0的原有倾向：

不再预先认定专项服务必须成为主要利润来源。

建议建立双引擎：

### 引擎一：规模化会员收入

负责：

- 经常性收入
- 客户经营档案
- 持续需求理解
- 日常信息和问题处理
- 长期客户关系

如果自动化充分，会员本身就可能形成较高的现金贡献。

### 引擎二：专项增值服务

负责：

- 深度经营诊断
- AI工作流定制
- 企业数字化建设
- 重大管理问题
- 复杂材料
- 其他专业项目

按照范围单独报价。

专项服务可以提升收入和专业价值，但不作为会员模式能够盈利的必要条件。

---

## 十六、协会合作的商业定位

采用已经确认的双重角色：

**参与或牵头协会经营服务板块，同时保留独立公司、产品和商业收益。**

第一阶段内部公益投入约每周2–4小时。

协会合作重点：

- 真实企业需求发现
- 企业间供需连接
- 专业资源协同
- 自愿转介
- 服务方法改进

现阶段不把协会视为确定付费采购客户。

也不把协会口头提到的会员数量作为已经拥有的销售客户。

协会共建本身可能帮助建立服务标准和专业资源网络，但需要防止公共服务工作无限扩大。

---

## 十七、项目真正需要开发的不是大量单独Agent

核心应是可以统一管理多企业服务的系统。

建议抽象为：

**一个客户经营档案底座 + 一个任务处理引擎 + 一个共享信息引擎 + 一个批量交付引擎 + 一个人工例外工作台。**

### 客户经营档案

保存每家企业经过授权的经营信息、关键指标和历史事项。

### 任务处理引擎

根据客户权益和经营情况，生成需要执行的服务任务。

### 共享信息引擎

统一采集、核实和管理可复用的公开信息。

### 批量交付引擎

批量生成个性化经营简报、提醒、材料及报告草稿。

### 人工例外工作台

集中展示：

- 高风险判断
- 信息来源冲突
- 计算异常
- 客户新需求
- 待人工审核内容
- 逾期及紧急事项

这样，经营驾驶舱的主要用途不是展示多少漂亮图表，而是：

> **让一个人能够管理更多企业，同时知道哪些事情必须亲自处理。**

---

## 十八、需要验证的自动化指标

不再单纯统计AI生成了多少份报告。

建议重点记录：

| 指标        | 计算方式或观察重点            |
| --------- | -------------------- |
| 单客户月人工时间  | 当月实际人工服务时长÷在服企业数     |
| 批量任务人工耗时  | 一批任务从准备到正式交付的人工总时间   |
| 自动生成可用率   | 无需实质重做、经必要审核可交付的初稿占比 |
| 异常处理率     | 需要额外人工排查的任务占比        |
| 客户数据更新成本  | 每次更新的实际人工时间          |
| 报告平均审核时间  | 报告正式交付前的人工分钟数        |
| 单客户额外现金成本 | 实际新增现金支出÷相关客户数       |
| 服务响应达标率   | 按套餐承诺及时响应的比例         |
| 客户实际使用率   | 阅读、反馈、问诊和行动使用情况      |

真正值得关注的变化是：

**从10家增加到20家客户，人工总时间增长多少？**

如果客户数量增加一倍，而人工总服务时间只增加少量，说明批量化开始产生效果。

但仍需同时观察质量、客户满意度和重要错误率。

## 十九、三个关键技术与经营约束

### 约束一：数据不标准化

即使AI很强，不同企业导出的数据字段、时间口径及业务定义仍可能不同。

如果每次都需要人工重新清洗，批量化优势会减弱。

因此应优先建立：

- 数据字段映射
- 可复用计算规则
- 数据质量检查
- 行业模板
- 企业个性化配置

### 约束二：人工即时响应

定期报告容易集中批量处理。

客户临时提出的问诊、电话和紧急事项却不一定能够批量处理。

特别是B02现有标准版2小时、顾问版1小时首次响应，形成了对人工值守的要求。

因此需要将：

**自动接收与分类、首次响应、实际处理完成**

分开设计。

不能把自动回复简单当成顾问已经履行全部响应责任。

### 约束三：人工审核责任

如果AI一次生成50份报告，不能因为数量大就自动发送未经核实的重要分析。

应根据风险等级区分审核方式：

- 普通事实性、格式化内容：采用规则检查与适当抽查。
- 经营数字与重要变化：确定性计算、来源核对与重点审核。
- 重大经营建议、敏感信息及高风险事项：人工明确审核。

自动化的目标是减少无效重复工作，而不是降低可靠性要求。

---

## 二十、验证规模如何安排

不以同时招募50家客户作为第一轮目标。

建议分三个容量验证阶段。

### 第一阶段：2–5家

验证基本服务闭环。

重点观察：

- 企业访谈是否能快速结构化
- AI能否生成可用报告
- 周报与监测流程能否稳定执行
- 客户是否愿意真实付费
- 首次建档实际工时

### 第二阶段：8–15家

验证同一系统服务多家企业。

重点观察：

- 批量报告效率
- 数据隔离和准确性
- 顾问审核时间
- 客户临时问诊频率
- 现金增量成本
- 正式会员转化与续费

### 第三阶段：20–30家

验证规模化经营的早期可行性。

重点观察：

- 每客户人工干预时间是否下降
- 固定AI订阅是否需要扩容
- 服务响应是否可靠
- 客户是否持续使用
- 是否需要外部支持人员

50家以上作为进一步容量压力测试场景，而不是目前已经证明可交付的规模。

---

## 二十一、商业决策标准

如果客户数量增长，而单位现金成本维持较低：

**优先优化订阅服务和客户留存。**

如果自动化效果良好，但客户付费意愿不足：

**优先调整价值表达、客群和产品，而不是继续压低成本。**

如果客户愿意付费，但临时问诊和个性化工作大量增加：

**优先优化套餐边界、分层服务与例外处理机制。**

如果订阅收入能够覆盖运营并带来稳定现金结余：

**不必为了追求高客单价而强行增加专项服务。**

如果专项项目具备明确需求和良好贡献：

**独立发展专项业务，避免占用过多正常会员交付能力。**

---

## 二十二、C02 V1.1最终结论

本项目应当优先被视为：

**AI驱动的规模化经营支持服务业务。**

而不仅是：

低价经营咨询业务。

其潜在竞争优势包括：

1. 共享信息处理降低重复研究成本。
2. 行业模板及程序计算降低重复分析成本。
3. AI批量生成降低周期性材料制作成本。
4. 统一任务管理降低运营管理复杂度。
5. 人工集中处理复杂问题，发挥个人专业经验。
6. 长期企业档案提高连续服务的针对性。
7. 协会及专业资源网络可以扩展服务范围，但不必由自身承担全部专业工作。

创始人未支付的劳动成本，不作为当前现金利润扣减项。

但必须持续记录人工干预密度，以判断客户容量和未来组织复制能力。

**如果这一模式得到真实运营验证，199元和399元会员不一定是低利润业务，反而可能成为具有规模效应的长期经常性收入。**

决定项目能否成立的核心，不是咨询服务收费是否足够高，而是：

> **客户愿意持续付多少钱，以及我们能用多低的真实边际成本、多少必要的人工干预，为他们长期提供可靠且有价值的服务。**
