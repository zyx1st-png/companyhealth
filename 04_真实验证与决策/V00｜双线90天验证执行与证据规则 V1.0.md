# V00｜双线90天验证执行与证据规则 V1.0

**状态：计划，不是完成报告。** 统一串联F01（会员）、B08（高级专项）、T01（技术）、D01/D02（会员试点）、C02（现金与工时）。启动日T0须在真实执行时填入；“第1天”不是文件创建日。

## 1. 三个互不替代的决策

- **M会员商业决策**：是否存在正式会员付费、使用与续费？99元体验不能替代正式会员证据。
- **P高级专项商业决策**：是否存在能够签约、收款并在范围内验收的高价值经营问题？报价不能替代合同，合同不能替代收款。
- **T技术扩张决策**：相同质量下程序/AI是否降低真实人工时间，且无严重数据隔离/数字风险？20家模拟周报通过不能推导真实20家完整会员服务容量。

允许M=Adjust而P=Go，或P=No-Go而M=Go。只有安全与合法经营门槛可共同阻断。

## 3. 必须准确计算的指标及分母

| 指标 | 计算方式 | 必须说明 |
|---|---|---|
| M体验付费率 | 实际已付款体验数 / 获得完整体验报价且可购买的有效线索数 | 过滤不适格线索；分渠道 |
| M正式转化率 | 已付正式会员数 / 已完成体验且进入转化观察窗口的客户数 | 未完成体验者标记未到期，不算拒绝 |
| M到期续费率 | 实际续费客户数 / 到期且具有合法续费机会的付费会员数 | 未到续费期=未观察到 |
| P报价成交率 | 已签约并达到合同生效条件的专项单数 / 已出正式有效专项报价数 | 报价撤回、变更、重复报价要记 |
| P首款到账率 | 实际收到启动款项目数 / 到达首款付款节点的有效项目数 | 合同额≠到账额 |
| P按约验收率 | 通过合同约定验收单数 / 进入约定验收阶段且到期项目数 | 未到期单列 |
| 人工单客工时 | 记录首次获客、首次建档、周期服务、问诊、共享、异常、返工及项目专项工时 | 工时类别不重复或遗漏 |
| 服务单位贡献 | 已实际确认收入 - 可归属额外现金支出 - 合理分摊共享支出 | 同时列不计工资的现金口径与人时/替代人工情景 |
| T01 E02改进率 | （逐家AI辅助人工分钟 - 批量人工分钟）/逐家AI辅助人工分钟 | 两组质量门槛相同；目标至少40% |
| T01 E02质量 | 跨企业泄露、编造关键数字、权益错误、重要未经核实断言等严重错误数 | 目标均为零；不能以平均修改率替代 |

每项必须有原始基数、分母、时间窗口、数据出处和复核人。分母为0则报告“暂无可计算样本”，不得展示为0%或100%。

## 4. 时间与钱分别统计

M会员按C02记录：共享任务、逐企维护、首次建档、获客、异常/返工、公益协会时间。P专项按B08记录售前、交付、修改、差旅、外包和回款。固定订阅费用不重复当作每家客户增量成本，会员抵扣的99元不能重复计为体验收入与首月收入。

按三张表并列：①实际现金收支；②服务可用时间与排队压力；③未来付薪人员/外包情况下的复制经济性。不能用“创始人不领工资”推断组织可复制。

## 5. 安全与服务质量阻断

- 发生跨企业资料误送、重大数字错误、无授权处理、未审自动发送等：暂停受影响的流程、保存安全的事件摘要、修复与复测；不能因业务数据好看就忽略。
- 现有价格权益不因内部成本超标而单方减少；对未来新单进行明确告知和重新报价。
- 机构服务人数、接触数、试点客户数、正式会员、专项订单分别报数。
- 真实企业财务、人员和聊天原文不提交GitHub。V01只放**空白模板或匿名聚合结果**；可识别记录留在经授权的独立安全介质。

## 6. 第30/60/90天裁决会

每次只用V01的可核验证据填写：M/P/T各自GO、ADJUST、NO-GO或**INSUFFICIENT EVIDENCE**；各自下一轮最小实验、资源上限、负责人和复查日期。

最终报告必须分辨：①“有人愿意付费”；②“交付后愿意重复付费”；③“现有人工能履约”；④“付薪团队仍有经济空间”。不可用①自动推出②–④。
